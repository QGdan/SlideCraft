# 质量升级实施方案（待审核）

目标：在保持来源真实、主要内容可编辑、六阶段审核的前提下，提高观点深度、图表解释力和整套视觉表现。第一轮以劳动观任务作对照，不直接推翻现有工作流或引入完整平台。

## 1. 六个 Skill 保持解耦，增加具体交付要求

| Skill | 下一版应承担的实质工作 | 给用户审核的产物 |
|---|---|---|
| ppt-intake | 除主题受众外，确认成功标准、喜欢/不喜欢的参考、课堂讲述与打印的优先级、允许哪些对象为图片 | 需求摘要＋两三个可比较的视觉方向说明；不让用户填冗长设计问卷 |
| ppt-outline | 形成问题、观点、证据、推理、限制、启示；检查标题串读是否推进论证；补具体案例 | 标题串读稿＋逐页内容卡＋证据缺口表；概念和观点在此审核 |
| ppt-template | 按资料的表达任务选模板和构图；定义数据、案例、关系图、行动页等变体 | 真实代表样页＋设计系统＋容量/图表/资产规则；不能只批背景 |
| ppt-compose | 根据内容卡选择合适载体，产出可编辑图表/表格/关系图；接通已经验证的模板和原生组件 | 原生三页试验稿，批准后再制作整套；对象映射与实际回读证据 |
| ppt-polish | 明确每页主视觉、信息主次、图表标注、跨页节奏与表达精度；列出改前改后 | 具体视觉差异与理由；如果只做字号和颜色修正，不能称已完成信息设计升级 |
| ppt-review | 分别判定内容、设计、工程；问题定位到页/对象/负责阶段，并复查修复效果 | 本次文件绑定的逐页缺陷表＋整套判断＋未验证项；用户审美结论独立保留 |

总控只调度和维护状态。CLI 不会自动执行模型策划，新增命令本身也不等于新能力。

## 2. 内容层：从“资料条目”到“可解释的观点”

在现有事实账本之外，拟新增版本化 `content-plan.json`，每页记录：

- `question`：这一页回答哪个问题。
- `claim` / `claim_kind`：结论以及事实、推论、规范判断或教学示例的类别。
- `evidence_refs` / `reasoning` / `limitations`：哪些材料支持结论、推理怎么成立、不能推出什么。
- `exhibit`：视觉证据的目的、候选载体、图上必须显示的结论或关系。
- `bridge`：它如何接到下一页或整个报告目标。
- `case_refs`：案例来源；编写情境必须显式标明示例。

先作为实验 sidecar，不向旧 spec 随意添加字段。当前 `deck.schema.json` 使用 `additionalProperties:false`；进入生产必须定义新合同版本、旧版适配及校验，再升级阶段提交。读取旧任务仍可查看历史记录，不能因规则升级伪造新批准。

内容检查重点：数字正确只是第一关；还要检查结论是否超出证据、概念是否准确、页面是否重复、是否存在能推动理解的具体情境。无需为了“研究更深”盲目增加来源数量或新数据。

## 3. 图表层：选图依据和样式分开

拟建立 `chart-plan`，绑定现有事实 ID 与派生公式，包含比较任务、类别/系列、单位、基数、缺失值策略、轴尺度、小数格式、强调对象和解释标注。

第一批只完善最常用且能验证的能力：

| 表达任务 | 优先载体 | 必要边界 |
|---|---|---|
| 比较类别 | 原生横条/柱图＋重点标注 | 条形长度从零开始；不把摘录项称完整排名 |
| 时间变化 | 原生折线 | 同口径时间数据；不把两次不同调查连起来 |
| 构成 | 原生堆积条或其他适合的构成图 | 核实互斥、完整和同一分母；多选题不适用 |
| 关系 | 原生散点候选 | 真实成对观测；不根据独立汇总值伪造关系 |
| 一个比例 | 大数字＋必要的上下文/比例图 | 避免图与数字重复占据半页；不臆测剩余类别 |

折线、散点等用于后续真实适用材料的回归样本，不强行塞进劳动观 PPT。第一轮重点改善条形图的解释力。

技术落点（均为拟实施）：

- 扩展 `engine/editorial_build.cjs` 的图表类型分派、轴、标签、主题和图内标注；去除演示业务的硬编码元数据。
- 把劳动观任务中的图表供体与 WPS 复制方法提炼为受支持的适配器，避免每个任务另写一套临时脚本。
- 保留现有事实—图表缓存—嵌入工作簿一致性检查；增加类别顺序、重点标注及派生值核对。
- WPS 本地 AddChart 新建曾失败，不将它作为唯一创建入口。原生图表先由已验证库生成，再复制和回读。

## 4. 模板与元素层：统一规则，允许有意义的变化

拟将模板分为设计 token、语义版式、对象资产三层。

固定字体家族、色板含义、标题层级、页边距与来源方式；允许封面、数据、概念、案例、行动页的布局变化。构图选择依据页面问题，不按“每三页必须换一种图”机械轮换。

第一批版式资产建议覆盖：数据结论、两种行为对照、判断路径、案例过程、带证据的行动安排，以及封面/结尾。每个记录适用任务、输入容量、必要对象、缩减/拆页策略和至少一个真实渲染样例。禁止超长后一路缩字号，禁止默默删除来源。

WPS 模板筛选仍属于 ppt-template。复用其原生信息图、表格、图片裁切和版式，不只取背景与角饰。会员模板保留来源和授权范围，不装入通用分发包。现有 automizer 实验继续扩到实际模板的文本长度、不同类别数及关系保留测试。

照片/生成插画只在承担场景说明或主题表达时使用。拟新增资产清单，记录来源、裁切、颜色、透明背景需求与允许的编辑级别；同套生成资产用同一视觉说明和参考，避免逐页独立生成导致风格漂移。

## 5. 审核层：内容、设计、工程各有结果

内容审核检查概念、来源、推理、相关性与具体性；设计审核检查主视觉、阅读顺序、图表解读、跨页节奏；工程审核检查打开、渲染、对象、数据、字体和备注。不得用平均分盖过错误或 unknown。

借鉴任务专属的二元问题，例如：

- 第 5 页能否直接看出应关注哪个求职属性，而不先阅读完整讲稿？
- 差值是否为同口径数据，是否标为百分点？
- 第 7 页是否正确区分需要与使用价值？
- 第 8 页是否能通过一个具体行为解释休整与逃责的区别？
- 第 11 页是否有能拿来验收的成果及分工证据？

另保留人工偏好评价：克制/有主题感、信息主次是否舒服、整套是否单调。二元清单不能证明每个人都认为好看。

返修记录格式拟为 `slide_id / element_id / defect / evidence / owner_stage / proposed_fix / recheck`。一般允许两轮定点视觉修复，仍无改善时定位内容或模板问题并上溯；不反复整页生图。用户阶段审核与内部修复循环分开，不能假造用户批准。

## 6. 实施顺序与审核点

| 阶段 | 实施内容 | 完成证据 | 审核/停止条件 |
|---|---|---|---|
| R0 基线 | 当前文件、副本、来源、预览绑定；定位打开失败并建立可渲染副本 | 本轮已完成结构基线；渲染问题仍待解决 | 无有效渲染，不宣称当前成品视觉终审完成；不覆盖用户原文件 |
| R1 内容与设计任务书 | 修正第 7 页概念，强化 5/8/11 页内容卡；给出继承现模板和升级视觉两种方案 | 标题串读、三页任务书、来源与允许改动表 | 用户批准内容与视觉方向后才能制作受控样页 |
| R2 三页对照 | 相同事实/结论下比较原版与信息设计新版；另列内容修订的影响 | 3 页可编辑 PPTX＋真实渲染＋修改记录 | 用户能指出明显改善，并接受整体风格；若效果仍一般，先修设计，不扩写全套 |
| R3 引擎与 Skill 集成 | 提炼验证有效的内容合同、图表选型、版式和适配器；六 Skill 各归其职 | 版本化合同、旧版适配、能力清单、针对性验证 | 样页表现能经通用流程复现，而非只在一次性脚本成立 |
| R4 整套复验 | 在保留 12 页/5 分钟约束下改完整 deck，并增加另一主题的适用样本 | 全页渲染、源数据/对象检查、用户效果审核 | 正式交付仍需实际检查通过；未知项保留，不靠加测试数量通过 |
| R5 可选设计源试验 | 只有原生路线确有表达瓶颈时，对复杂页试验 PPT Master | 同内容/同要求对照、原生/位图边界、成本与回退记录 | 效果与编辑性没有可见收益则停止，不进入默认生产 |

这里只建议按交付物推进，不承诺固定 90 天或未经标定的通过率。记录实际研究、制作、审核、返工时间和工具费用；样本足够后再制定指标。

## 7. 本次需要审核的范围

建议先同意 R0—R2 的范围：解决当前版本的渲染基线，用第 5、8、11 页验证图表、辨析、行动三个改进方向。视觉上可先保留酒红/深蓝与字体，允许削弱背景装饰、改变内部构图；这是候选方向，尚未被用户批准。

R3—R5 是后续路线，不应在三页结果尚未证明有效前全部实施。研发动作与 PPT 内容/模板审批分别留档。
