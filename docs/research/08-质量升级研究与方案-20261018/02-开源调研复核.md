# 开源调研复核与采用决定草案

日期：2026-10-18。结合 `07` 的报告、路线图、项目卡片、既有 P4 实验和上游官方文档复核；本轮未逐一重跑 30 个项目。下列项目均未在本轮新安装，文档能力与本机验证分开记录。上游链接多为 main 或滚动文档，进入试验前应固定 commit/依赖锁与文件哈希。

## 值得采用的部分

| 项目/能力 | 官方资料本轮确认 | 对当前项目的具体价值 | 采用建议 |
|---|---|---|---|
| PptxGenJS | 官方列出折线、散点等图表及组合图接口 | 图表贫乏不能归因于底层库；主要需要扩展本项目的选图、参数和注释能力 | 保留主引擎，先加强常见图表及标注。[文档](https://gitbrent.github.io/PptxGenJS/docs/api-charts/) |
| pptx-automizer | 支持常见形状/表格/图表；动画不同步，母版与版式操作有边界 | 把设计好的原生组件和模板作为可复用资产 | 延续已有隔离实验，增加真实模板与不同内容容量测试，不从头重做同一 POC。[限制](https://singerla.github.io/pptx-automizer/limitations) |
| PPT Master | 使用项目受约束 SVG；默认图表/表格可为形状，数据对象需显式原生导出路径 | 值得试验复杂关系图和更自由构图，保留明确的编译边界 | 独立试验，不替换现有主线；不承诺任意 SVG 或 AI 图片自动变成原生图表。[技术设计](https://github.com/hugohe3/ppt-master/blob/main/docs/technical-design.md) |
| PPTAgent Skill | 宿主编写页面，CLI 渲染/转换；页面源与导出 deck 分别审查，资源变化使审核失效 | 借鉴设计稿和最终文件的双重检查，以及完整的修复后重审 | 保留现有哈希失效机制，补“语义与设计问题是否真的修复”。[Skill](https://github.com/icip-cas/PPTAgent/blob/main/skills/pptagent/SKILL.md) |
| academic-pptx-skill | 行动标题、只读标题能否讲通、结果图上直接标结论 | 加强论证链和展品纪律 | 采用通用设计思想，自写适合中文的规则；不照搬它对色彩、图标等一刀切限制。[项目](https://github.com/Gabberflast/academic-pptx-skill) |
| PresentBench | 按任务设置细粒度二元检查问题 | 把“好不好”拆成与本次简报有关的可核查问题 | 借鉴评估方式；不把通用打分当作用户审美认可。[项目](https://github.com/PresentBench/PresentBench) |

本项目已有 `xparse-parse`，文档解析不是本次最急缺口。Presenton、Dify/n8n 等平台化能力也暂不构成图表和内容质量的直接解法。

## 需要调整 Claude 方案的判断

1. **“先 review”应与生成能力一起做小闭环。** 现有项目已具备独立审核、原生数据检查、审批哈希与修改后失效。当前暴露的缺口包括大纲本身抽象、图表强调不足、关系图没有落实。只继续增加检查项，可能更准确地说明 PPT 一般，却不能产出更好的 PPT。
2. **不能将已有能力当成未建。** `experiments/p4/refill.cjs` 已有 automizer 填充与图表/工作簿实验；WPS 有真实模板副本编辑和原生元素实测。下一步是正式适配、内容容量和语义选型，不能只增加“已接通”证明。
3. **E0—E4 可作粗略说明，不能直接作为唯一门禁。** 概念页没有图表不应因此降级；普通 PPTX 本来就有 layout 关系，存在关系不代表继承了有用的设计。大量可编辑装饰形状也不应掩盖核心图表被栅格化。改为按对象用途检查：正文、数据图、表格、关系图、插画各自满足需求。
4. **“设计自由度高只能走 SVG/HTML”过于绝对。** 优秀原生模板、PptxGenJS 原生构图也能有高质量。SVG/HTML 是设计与编译路线，不能代替设计能力。
5. **PPT Master 的默认形状输出不等于数据原生图表。** 要分别检查可选对象能力、数据工作簿、编辑保存和目标软件渲染。其官方当前技术设计还区分可选视觉自检，不能直接替代本项目强制终审。
6. **许可记录需要文件级核对。** academic-pptx-skill 的根 LICENSE 和 README 写 MIT，但本轮读取的 SKILL.md 仍含 Proprietary/缺失 LICENSE.txt 的元信息。记录冲突，若复制文件需先澄清；本方案只用通用叙事方法并自行编写规则。[根许可](https://github.com/Gabberflast/academic-pptx-skill/blob/main/LICENSE)、[Skill 元信息](https://github.com/Gabberflast/academic-pptx-skill/blob/main/SKILL.md)。其余未重点核查项目不重复作新的许可背书。
7. **70% 一次通过率、80% 编辑覆盖、90 天排期都是建议值。** 不是本项目已测结果，也不是上线保证。先用真实失败案例标定有意义的验收，再决定扩展规模。

## 建议的技术组合

保留现有六阶段和事实账本。以 PptxGenJS/现有原生图表供体生产数据对象，WPS 复用会员模板及实际编辑/渲染，automizer 在能力验证后承担离线模板复用。复杂关系图先用现有原生对象路线；PPT Master 作为对照候选。

生图用于封面、场景或插画；标题、数据、关系标签保持原生。生成图片不会天然获得元素编辑性。Figma/Canva 可成为设计来源，但其本轮完整编辑与 PPTX 导出链路未验证，不能写成已经工作的必选依赖。宿主生图工具没有暴露模型 ID 时，不声称强制调用了某个指定型号。
