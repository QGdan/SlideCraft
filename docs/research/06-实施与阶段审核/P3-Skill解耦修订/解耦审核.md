## 各阶段的分工

需求 Skill 先读已有信息，分轮问关键问题，将真实回答、假设和未回答项分开。大纲 Skill 读取资料、标注来源与口径，再组织逐页主张。模板 Skill 先确定整套视觉系统，展示真实模板样页，明确引擎适配边界。

制作 Skill 保持批准过的内容与模板，输出原生对象；事实和结构变化退回大纲，品牌变化退回模板。美化 Skill 可以调整版式、增加图形、精简非事实正文，但不能改数字、口径、流程含义或已批准主张。审核 Skill 独立读取实际成品和图像，既能指出视觉缺陷，也能保留未验证项；审核过程不偷偷改稿。

## 命令如何调用 Skill

```powershell
# 在 ppt-workflow 目录，用项目虚拟环境运行
.\.venv\Scripts\python.exe -m ppt_workflow skills
.\.venv\Scripts\python.exe -m ppt_workflow intake --workspace runs/my-stage-job
```

第二条命令返回 ppt-intake 的绝对 SKILL.md 路径、期望产物和当前交接状态。宿主读取该 Skill，完成访谈并整理需求文件，然后提交：

```powershell
.\.venv\Scripts\python.exe -m ppt_workflow intake --workspace runs/my-stage-job --input requirements.json
```

命令不会启动语言模型、自动提问或自动判断画面。它负责把阶段绑定到正确 Skill，并校验、保存交接件。真实提问、研究、模板设计、制作、美化和视觉判读由加载对应 Skill 的宿主执行，不能把命令退出成功当作这些工作已经执行。

草稿提交后返回准确的 artifact_sha256。用户确认具体产物后，用 --approve <该哈希> --reviewer user --evidence "真实审批依据" 登记，再进入 outline，以相同方式继续 template、compose、polish、review。不重新索要同一份已有授权，不伪造审批。完整协议见总控 Skill 的 references/stage-handoffs.md。

## 交接与退回已落实

- 必须信息缺失时为 needs_input，不能审批或进入大纲；可选偏好不阻塞。
- 每个交接件保留版本、附件哈希、Skill 整包哈希、校验器/路由版本及上游批准件哈希。
- 上游内容、来源附件、模板或 Skill 规则变化时，下游失效；旧文件与批准记录保留，不能只改状态绕过。
- 大纲页数、事实定位、证据引用需有效；模板必须有真实 PowerPoint 布局和预览图片。
- 制作阶段核对已批准主张、事实、原生对象与实际模板绑定；不是只检查 JSON 中写了一个模板名字。
- 美化允许新增原生图形和非事实正文润色；事实、核心主张和品牌变化会被退回。
- 审核绑定美化后的 PPT、spec、原自动 QA 和全部渲染图；不允许删除 unknown 再写 passed。
- 对未验证审核报告的阶段批准，只表示接受审核判断，不等于正式发布。原 deliver 门禁继续保留。
