# 视觉素材、Office 与 Figma

## 插画

先固定整套模板，再统一插画的背景、主色、材质、光源、构图和裁切范围。优先生成透明的局部图形或有充足留白的场景，不把正文、真实数字或图表刻进图片。需要生成/编辑位图时使用宿主 imagegen 工具及其可用 Skill；工具未公开模型 ID 时不能声称强制调用了某个具体模型。

资产通过项目 `ppt_workflow.assets.register_asset` 登记路径、SHA256、来源、许可说明和提示词记录。spec 中 image 的 asset_id/path 与登记信息一致。资产变化会使旧审核失效。

可编辑需求分两类：原图只改位置、裁切和大小，可保留位图；需要改结构和文字时，用原生对象或 SVG 做语义重建。标明重建的近似程度，不声称 PNG 能自动无损还原为图层。

## Office

CLI 使用项目官方 MCP SDK 客户端和本地 Office worker，实际调用 PowerPoint 来应用原生模板、图表和对象。它不代表已经把项目 MCP 注册进 Codex 全局配置。WPS 当前未验证，不从安装状态推断已连接。

已有 worker 会校验 Office 会话归属、输入哈希、超时和清理结果。清理不确定时保留隔离锁，不接管现有用户进程。当前 SmartArt 枚举不可用，用原生可编辑图形组合，并说明能力差异。

## Figma

Figma 属于宿主插件编辑通路，不由本地 CLI 自动登录。插件可用且用户要求编辑时，加载当前环境的 `figma-create-new-file`（新建文件时）、`figma-use`、`figma-use-slides` 等对应技能，按实际工具调用。不要仅因安装过插件就假设仍可连接。

已有文件按 ID 修改；新文件先调用 whoami 决定归属，只有一个团队时直接使用，多个团队按该插件要求选择。中文字体先查询可用字体，再载入准确的 family/style。

在 Figma 中重建文字、形状和流程，图片通过 upload_assets 上传；SVG 可导入为可编辑矢量树。Slides 节点先 appendChild 再设 x/y；语义相关元素分组，主题颜色和文字样式统一绑定。截图检查之后保存 file URL、节点与 spec ID 映射、字体差异和编辑边界。

Figma 的形状图表不等于 PowerPoint 的工作簿数据图表。在线设计修改不会自动写回本地 PPT；未经真实导出、重新渲染与对象检查，不声称完成可编辑往返。
