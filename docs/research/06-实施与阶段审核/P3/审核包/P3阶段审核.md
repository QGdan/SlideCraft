## 实现内容

| 命令 | 已实现行为 |
|---|---|
| doctor | 检查项目运行时、依赖和 Office 注册；不把注册成功当作 COM 或插件已连接 |
| plan | 验证 brief/spec、事实表、模板审批及统一风格；冻结来源、图片、模板、设计、生成器和 Node 哈希，输出 outline |
| build | PptxGenJS 生成并规范化，经项目官方 MCP SDK 客户端调用独立 Office worker 应用原生 POTX；支持不变输入断点恢复 |
| qa | 绑定结构、原生数据、模板一致性、Office 渲染与逐页视觉记录；未知检查继续保留 |
| revise | 只允许有 QA 定位证据的正文框在原位置小幅扩大，不改事实、字体、品牌和共享页眉页脚；新版本不继承旧审核 |
| deliver | 校验 ready、QA passed、零未解决 warning/unknown、有效视觉记录及所有哈希；复制后再次校验，生成来源副本、清单和 ZIP |
| benchmark | 汇总真实本地构建/渲染时长、QA 状态；未知费用及人工修改耗时保留 null |

状态保存在每个任务的 state.json。每次修订独立目录，构建与 QA 各次尝试保留日志。最多两轮局部修复、全任务一次显式环境重试；视觉 API 调用前通过 ticket 预留额度，含失败最多三次。CLI 不自动发送图片到外部视觉 API，当前使用宿主图像审阅。

当前 CLI 支持 unified-v3 十类版式组合为 8–20 页。已移除 Office 内容增强记录中的十页硬编码，流程步宽按节点数量计算。真实功能探针分别核对 8 页与 20 页的 Office 数量、布局记录和 PNG 数量。探针是机械验证材料，不是已批准的展示稿。

图表通路目前限单系列、两类别横向条形图；表格限三列。未支持的图表类型在构建前拒绝，不会静默生成错误类型。

## 运行与证据

在 ppt-workflow 目录：

```powershell
.\.venv\Scripts\python.exe -m ppt_workflow doctor
.\.venv\Scripts\python.exe -m ppt_workflow plan --config examples/workflow-unified.json --out runs/my-job
.\.venv\Scripts\python.exe -m ppt_workflow build --run runs/my-job --with-qa
```

真实一条命令演示：

```powershell
.\.venv\Scripts\python.exe scripts/run_p3_demo.py --run runs/new-demo --out ../06-实施与阶段审核/P3/new-demo
```

输出目录必须不存在。示例数据、设计与模板已依据 G2 的“继续”授权绑定；更换内容或模板后需要对应的新设计审核。

最终实际任务为 runs/p3-unified-cli-003，命令记录见本目录“最终运行”。十页构建约 16.03 秒、渲染约 12.08 秒，是本机单次测量，不代表其他任务性能。最初两次演示目录保留开发轨迹；最终证据以 003 为准。

已执行的失败演示：未审核输入被 plan 拒绝；规划后配置变化使 build --resume 失效；无真实 QA 定位依据的内容改动被 revise 拒绝；逐页视觉审阅后仍有未知检查的任务被 deliver 拒绝。正式 release 目录未创建。

## 尚未通过的正式交付条件

真实候选稿静态检查没有 error/warning；视觉阶段通过，但整体 QA 仍为 unverified，剩余 19 项 unknown。包括完整 OOXML schema 校验、交互编辑往返、图表标签布局测量、表格样式继承和文字排版估算的覆盖限制。人工查看画面不等于执行这些检查，因此不删除它们，也不把整体状态改成 passed。

本目录的“审核包”及 ZIP 是阶段候选资料，不是 deliver 命令放行的正式 release。正式交付正向路径已在隔离测试中验证；真实材料的正式放行仍受这些既有检查覆盖限制约束。若未来接受有限覆盖的发布策略，需要明确修订验收约定，本轮没有自动放宽。

Figma、图像生成通过宿主工具使用，工作流已写明操作和证据要求；本地 CLI 不自动登录这些服务。WPS、任意学院/品牌模板、Figma 到 PPTX 的可编辑往返和外部引擎对照尚未验证。
