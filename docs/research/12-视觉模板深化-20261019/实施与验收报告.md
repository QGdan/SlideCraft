日期：2026-10-19。主线是项目与Skill优化，本轮补充真正可复用的场景模板与图片排版。没有重做或覆盖旧12页客户稿，也没有登记业务审批。

- [当前工作流安装包](交付/PPT工作流-场景模板深化-20261019.zip)。

新增一个原创模板家族，两种变体、四种构图：场景封面、证据与解释、情境对照、场景与行动。它们是内容不同的专用布局；不是四张背景图，也不是四套独立模板。

与上一轮相比，封面和行动页加入有主题的空间场景，证据页仍用原生图表，对照页保留可编辑信息关系。图片在需要时出现，不把每页都做成照片或卡片。主观风格是否合意仍由用户审核，不用测试数量代替审美判断。

## 已进入项目的实现

| 部分 | 实际改动 |
|---|---|
| 可复用模板 | templates/campus-editorial-v1/blueprint.json统一语义色、字号、图片位置、字段和容量；改内容时复用构图 |
| 构建器 | ppt_workflow/blueprints.py把结构化字段编译为原生对象，输出实际命名布局、design-system、spec与检查报告 |
| 图片排版 | engine/image_compile.cjs提供contain/cover；cover通过焦点控制裁切，保留原图字节；旧输入不指定fit时保留旧行为 |
| 审核绑定 | 模板SHA256写入spec，旧版本或无效变体拒绝；新模块、模板与引擎参与规则摘要，旧批准不能静默沿用 |
| CLI分工 | template-catalog归模板Skill，blueprint-build归制作Skill；不创建或批准业务阶段 |
| 独立Skill | 总控、模板、制作、美化、审核各自更新对应规则及参考；需求和大纲职责保持独立 |
| 素材 | 宿主imagegen生成一张无文字场景，登记来源、完整提示词和哈希；未新增API key或虚构模型ID |

字段超容量会拒绝，不靠缩字凑页。该证据布局最多6类别、2系列；通用图表编译器的12类别、4系列能力没有被误当成任意布局均可容纳。

旧unified-v3计划构建链保留，新路线是独立蓝图构建。实际生成的PPTX含命名原生layout，可以作为模板阶段的真实样件；蓝图JSON不是POTX。未实现任意用户模板的XML原样复制，也没有以此替换用户品牌。

## 研究如何融合

核对了Presenton Skills、pptx-gen、Tahta、ImageGen PPTX Pipeline与Slidev官方主题，下载固定提交的文档、Skill及许可，未执行上游代码。具体版本、方法和未采用部分见[开源研究与迁移](开源研究与迁移.md)。

核心迁移是：字段化模板、语义token驱动多布局、图片与真实内容分层、按实际导出结果复查。没有复制第三方代码、模板或图标；Slidev的代码与图片许可不同，其素材没有进入交付包。没有机械采用上游固定轮数、4K或超分要求。

## 真实验证与返修

- 全量295项测试通过，便携155项通过，含新增18项模板、图片比例、裁切焦点、容量、资产、原生布局与旧版本兼容检查。[最终日志](regression-final/verification.json)
- 两个变体均用PowerPoint16.0/build20430导出，共8页1600×900；逐页查看并保存哈希。72个文字框未发现超过2pt的边界溢出，图内标签另作视觉检查。[渲染证据](render-evidence.json)
- 深色封面首次页码落在浅图上，对比不足；已移回文字区并重渲染。最终八页未见明显文字裁切、主体被误切或数据标签挤压；这不等于全面排版认证。
- 在独立副本实际改标题、改变图片裁切、保存重开；裁切值一致回读，原图字节保留。原生文字、图表cache/工作簿和布局独立检查通过。[操作记录](edit-scene.json)、[独立检查](native-after-edit.json)
- cover在实际PowerPoint样页中验证；contain的本轮验证是比例与居中计算测试，不能冒称已单独执行GUI往返。
- 七个Skill结构校验、备份及同步完成，保留安装版本的绝对项目绑定。[校验](skill-validation.json)、[同步](skill-sync.json)
- 安装包280个文件校验后在全新目录离线安装，使用自身依赖运行155项测试，并查询模板目录。[安装](package-installation.json)、[包核验](package-verification.json)

初次工程验证遇到不同报告目录同名regression导致质量预检输出冲突，已修正验证器使用完整证据路径摘要生成运行目录，再完成最终验证；旧失败记录保留。Skill验证首次使用系统GBK读取失败，改为UTF-8运行后全部通过，没有改动Skill内容来迎合编码错误。

## 调用方式

业务制作仍用 `$ppt-quality-workflow`；每个阶段实际由对应独立Skill执行并审核。新模板直接调用方法见[场景模板与分层视觉](../ppt-workflow/docs/场景模板与分层视觉.md)。

```powershell
# 在ppt-workflow目录执行
.\.venv\Scripts\python.exe -m ppt_workflow template-catalog
.\.venv\Scripts\python.exe -m ppt_workflow blueprint-build --input examples/campus-blueprint.json --out runs/new-scene-job --node D:/node/node.exe
```

needs_review与退出码2表示已构建候选待审核。命令不自动研究、改事实、选择用户品牌或作审美签字，release_allowed保持false。

## 边界与交付状态

图片内部像素不能原生编辑；可替换、可裁切的是图片层。标题、正文、数字、图表、对照与行动节点才是原生对象。没有承诺把AI图片任意拆成可编辑元素。

本轮仅增加一个适合校园服务/教学案例的家族；不是通用行业模板库。场景人物为AI示意，活动未实施，资料来自旧案例而非新调查。商业、学术及严谨品牌场景仍需适配与审核。
