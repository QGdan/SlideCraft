# 图片与原生图表联合表达

2026-10-22，已实现，供用户审核F。

这轮把通用制作入口从“每页一个主要视觉”扩展到一种明确的双证据构图：左侧图片，右侧紧凑原生比较图。大纲分别声明两个必需visual，素材包分别准备，最终页保留两项来源和对象映射。旧单视觉页、封面/章节/结尾继续兼容。

## 自动化顺序

1. 大纲写清图片和图表各自解释什么、如何共同支持主张，保留真实正文及来源。
2. 模板比较单图表与联合页，用真实图片比例、类别标签和文字体量选构图。
3. 制作准备图片，并用compact-chart-prepare制作对应紧凑图表；不直接缩小原先整幅图表和侧边结论。
4. 将两项素材及实际预览封存到material-pack，通过brief-compose按image-chart合并。
5. PowerPoint/WPS导图查看主体、标签、来源和密度，再交用户审核。内容或数据变化时重建对应素材及下游，保持原版本。

## 实际样例

[两页PPT](审核F/图片与图表联合表达-两页样例.pptx) · [两页预览](审核F/两页预览.png)

第一页单独呈现图表，第二页将相同数据与相关校园场景并排。数据是本地三份真实文件的原始像素宽度：1672、2560、1672px，采集记录含文件路径、字节哈希、尺寸和事实JSON。它不是业务成效，也不是图片美观评分。左图的字节哈希与被测校园素材一致，生成场景标识可见。

两页均由通用入口制作并在PowerPoint实际导出查看，图表保留原生对象和数据；图片保持可替换。54项受影响检查通过，四个相关Skill已同步，原客户文件未改动。用户审美意见尚未代填。

## 调用

在ppt-workflow项目虚拟环境运行：

```powershell
python -m ppt_workflow compact-chart-prepare --input examples/compact-chart-metadata.json --out runs/新任务/紧凑图表
python -m ppt_workflow brief-compose --input examples/brief-composition-paired.json --out runs/新任务/composed --node D:/node/node.exe
```

第一条重现本轮紧凑图表；第二条使用本轮已封存的两项素材复现两页。新题材使用自己的实际资料、素材包、事实和布局选择，不能直接照搬这些元数据。输出路径保持新建。

准备过程示例在prepare_evidence_example.py：测量文件→写事实来源→准备原生图表与图片→导出native-build→material-pack→brief-compose→导出最终render。实际最终运行目录为ppt-workflow/runs/paired-evidence-20261022-001。

更多字段与分工见[图片与原生图表联合表达](../ppt-workflow/docs/图片与原生图表联合表达.md)。

## 支持范围

当前固定常规宽屏、微软雅黑、一张图片＋一个非负横条图、2–4个短类别和一个系列；概述最多一行。更多必需素材、长篇解释或复杂系列应选择其他构图，不删文、不删数据凑页。

本轮没有调用生图模型或重测在线素材服务，未把原生对象检查等同于交互编辑保存往返，也未执行全文OOXML模式校验。项目能力有实际样例和输入可复用，正式业务阶段仍遵守原来的大纲、模板与成品审核。
