# 先补“内容怎样成为页面”的能力

本轮最值得迁移的是三个机制：**按内容关系选构图、用真实内容验证模板容量、将素材风格与页面风格放在同一份设计说明中**。保留现有六阶段、事实账本、任务素材包和 Office/WPS 接口，围绕它们补生成能力。

我们的项目已经能把文字、图片、常见原生图表和简单步骤组织成 PPT，也有来源和导图检查。仍容易得到一般效果的原因，在于生产中间层偏薄：大纲给出了主张与视觉用途，但“这些内容是什么关系、哪一种原生结构最适合、正文多长时怎样调整”还主要依赖当次临时决定。

## 建议的执行顺序

1. **先补原生结构的真实实现。** 当前 editorial 出口的 diagram/smartart 分支只是画矩形；先明确拒绝不支持的对象，再实现带节点、分组和连接线的关系图。已有展开成普通对象的模块继续保留。
2. **补详细大纲中的内容关系和选择理由。** 给出一页需要解释什么、已有证据怎样支持、元素间是顺序/对照/层级/因果还是组成；由这些信息选择表达。
3. **增加少而完整的原生构图配方。** 先做证据主导、对照、步骤产出、层级关系、趋势注释、图片叙事等最常用类型。每个配方都有真实内容样例、容量、原生对象和适用条件。
4. **改进模板选型与素材一致性。** 用真实封面、正文和数据页选择模板；图片/插画继承同一份风格说明，逐资产保存提示词和参考。
5. **加入中文文本测量及局部适配。** 从长标题、混排正文、注释三个常见问题开始；需要时换构图或拆页，不靠默默缩字、裁字解决。

每一步用真实任务的几页说明改进效果，保留原有阶段审核。无需先重搭整个平台、再引入一套 API 编排或把主要精力转回自动评分。
