## 1. presentation-skill：把设计决策落到可执行布局

### 实际链路

`SKILL.md → brief/outline → composition_grammar_catalog → role contracts → render_plan → renderSlide → slides.js/readable_role_layouts → PPTX`

它区分整套叙事风格、每页的故事任务、渲染角色与主题处理。风格不再只是色板；八种语法为标题、证据、比较、图表、表格、决策等角色提供不同的阅读结构。归一化槽位定义区域、主锚点与阅读顺序，渲染器再转换为具体几何。[源码 composition_grammar_catalog.md:1](https://github.com/siril9/presentation-skill/blob/efd899c5ddf866af2ce0001c4c9340af775d4d55/plugins/presentation-skill/skills/presentation-skill/references/composition_grammar_catalog.md#L1) [源码 role_layout_contracts.py:49](https://github.com/siril9/presentation-skill/blob/efd899c5ddf866af2ce0001c4c9340af775d4d55/plugins/presentation-skill/skills/presentation-skill/scripts/role_layout_contracts.py#L49)

`route_composition_grammars()` 将用户要求、已选风格和关键词匹配综合排序，返回主方案与最多两个备选；选中风格可锁定对应语法。这是可解释的确定性筛选，再交给代理判断，不是内容语义理解已完全自动化。[源码 composition_grammar_catalog.py:255](https://github.com/siril9/presentation-skill/blob/efd899c5ddf866af2ce0001c4c9340af775d4d55/plugins/presentation-skill/skills/presentation-skill/scripts/composition_grammar_catalog.py#L255)

### 比提示词更有价值的实现

- `readable_role_layouts.js` 用横排/纵排组成布局树，根据文字占高分配空间；多余项目有继续展开的分支，避免只截取前几个。
- `space_allocation.js` 先从底部预留来源、注释等区域，再算主内容剩余空间。放不下则要求更宽布局或拆页。
- `renderSlide()` 不仅分派到图表、图片、流程等函数，还记录实际应用的布局适配器及回退原因，可以追踪“计划的布局有没有真正使用”。[源码 readable_role_layouts.js:190](https://github.com/siril9/presentation-skill/blob/efd899c5ddf866af2ce0001c4c9340af775d4d55/plugins/presentation-skill/skills/presentation-skill/templates/pptxgenjs/readable_role_layouts.js#L190) [源码 space_allocation.js:6](https://github.com/siril9/presentation-skill/blob/efd899c5ddf866af2ce0001c4c9340af775d4d55/plugins/presentation-skill/skills/presentation-skill/templates/pptxgenjs/space_allocation.js#L6) [源码 build_deck_pptxgenjs.js:1601](https://github.com/siril9/presentation-skill/blob/efd899c5ddf866af2ce0001c4c9340af775d4d55/plugins/presentation-skill/skills/presentation-skill/scripts/build_deck_pptxgenjs.js#L1601)

### 不宜直接照搬

`wrapText()` 按空白切词，并对单个词超宽直接抛错。它虽按宽字符估算宽度，但无空格的中文长句仍可能整个进入“单词”分支；这是静态代码可见的兼容性风险，本轮未运行中文复现。应借鉴测量驱动分配，改用中文断行和目标字体测量。[源码 readable_role_layouts.js:51](https://github.com/siril9/presentation-skill/blob/efd899c5ddf866af2ce0001c4c9340af775d4d55/plugins/presentation-skill/skills/presentation-skill/templates/pptxgenjs/readable_role_layouts.js#L51)

`alternate` 在基础槽位变换中是水平镜像，`dense` 是扩张区域，不应把每个变体名称都当成完全不同的新设计。风格原子里部分字段只是写入设计信号，并非自动兑现成配色或新图形；须追踪后续消费。复杂规划合同也不必整套带进我们的六阶段。[源码 role_layout_contracts.js:66](https://github.com/siril9/presentation-skill/blob/efd899c5ddf866af2ce0001c4c9340af775d4d55/plugins/presentation-skill/skills/presentation-skill/templates/pptxgenjs/role_layout_contracts.js#L66) [源码 apply_atom_composition.py:104](https://github.com/siril9/presentation-skill/blob/efd899c5ddf866af2ce0001c4c9340af775d4d55/plugins/presentation-skill/skills/presentation-skill/scripts/apply_atom_composition.py#L104)

**迁移建议：** 优先移植“内容关系→角色→配方→容量适配→原生对象”的模式。第一批不需要八套完整系统，先实现常用结构；保留当前事实绑定和项目目录约定。

## 2. PPT Master：表达范围、模板与数据对象拆得更细

### 实际链路

`路由入口 → Strategist/plan-core → design_spec/spec_lock → 素材准备 → Executor SVG → DrawingML 转换 → 可选原生 chart/table → PPTX 包`

`plan-core.md` 明确区分沟通目的、阅读方式、内容关系和资源需要：同一份材料是现场讲述还是供事后阅读，会改变密度和信息承载；顺序、对照、层级、归属等关系先写清，再由制作阶段决定形状。它还区分必须保持的事实/关系与可以调整的宏观构图。[源码 plan-core.md:9](https://github.com/hugohe3/ppt-master/blob/604ecdec8dd6a0405e1abdb49565430902373276/skills/ppt-master/references/plan-core.md#L9) [源码 plan-core.md:54](https://github.com/hugohe3/ppt-master/blob/604ecdec8dd6a0405e1abdb49565430902373276/skills/ppt-master/references/plan-core.md#L54)

### 模板不只是截图

`template_text_slots.py` 提取文字选择器、角色、当前文本、分段以及 tspan 数量；文字拓扑和属性另有哈希。这样模型拿到可替换内容，而工具还能保护不应随换字被破坏的结构。它针对的是 SVG 模板镜像槽位，不能原封不动当成我们原始 WPS shape_id 接口。[源码 template_text_slots.py:90](https://github.com/hugohe3/ppt-master/blob/604ecdec8dd6a0405e1abdb49565430902373276/skills/ppt-master/scripts/template_text_slots.py#L90)

### SVG 与原生对象的边界

普通矩形、线、路径等走 DrawingML；原生数据对象采用显式标记和 JSON。导出加 `--native-charts-and-tables` 时，转换器实际生成 chart XML、关系以及 embedded workbook；缺少该参数时是可编辑形状构成的图形。最新固定版本包含更广的图表数据类型与 ChartEx 实现，本轮重点读了常规图表和工作簿分支，没有对所有图型做兼容性审计。[源码 native-data-interface.md:20](https://github.com/hugohe3/ppt-master/blob/604ecdec8dd6a0405e1abdb49565430902373276/skills/ppt-master/references/native-data-interface.md#L20) [源码 __init__.py:410](https://github.com/hugohe3/ppt-master/blob/604ecdec8dd6a0405e1abdb49565430902373276/skills/ppt-master/scripts/svg_to_pptx/native_objects/__init__.py#L410) [源码 workbook.py:38](https://github.com/hugohe3/ppt-master/blob/604ecdec8dd6a0405e1abdb49565430902373276/skills/ppt-master/scripts/svg_to_pptx/native_objects/workbook.py#L38)

### 迁移方式

先吸收信息关系、语义分组、原生形状词汇和模板槽位模型，增强现有 scene-spec。复杂 SVG 编译如要用，应作为单独适配器接入，继续复用事实账本。不要一次换掉主引擎，也不要把其确认界面、语音、动画、完整锁文件体系全部引入；那些不是我们当前最缺的生成能力。

## 3. 宝玉 baoyu-slide-deck：风格与逐页视觉说明值得学

### 实际链路

`分析原文 → 确定风格与用途 → outline.md → prompts/逐页说明 → 逐页图片 → merge-to-pptx.ts`

大纲同时记录叙事目标、真实文案、视觉描述和构图；整套风格在同一个 STYLE_INSTRUCTIONS 块中保存，后续逐页提示词读取该块，而不是各自重新理解预设。风格拆成材质、情绪、字体外观、密度，并可记录参考图按 style/palette/direct 使用。[源码 outline-template.md:140](https://github.com/JimLiu/baoyu-skills/blob/1567581c26ec29f4216c6e6835415bf30343b0e3/skills/baoyu-slide-deck/references/outline-template.md#L140) [源码 outline-template.md:211](https://github.com/JimLiu/baoyu-skills/blob/1567581c26ec29f4216c6e6835415bf30343b0e3/skills/baoyu-slide-deck/references/outline-template.md#L211) [源码 SKILL.md:1](https://github.com/JimLiu/baoyu-skills/blob/1567581c26ec29f4216c6e6835415bf30343b0e3/skills/baoyu-slide-deck/SKILL.md#L1)

### 实际输出不是正文原生重建

`merge-to-pptx.ts` 按页号找图片，每页调用 `addImage()` 铺满；备注可带基础提示词与逐页提示词，没有重建图中正文/图表的逻辑。它的“修改”通过先改该页提示词、再重生成图片实现，适合局部画面迭代，但无法直接满足我们的图表数据可编辑要求。[源码 merge-to-pptx.ts:86](https://github.com/JimLiu/baoyu-skills/blob/1567581c26ec29f4216c6e6835415bf30343b0e3/skills/baoyu-slide-deck/scripts/merge-to-pptx.ts#L86)

**迁移建议：** 让任务素材包保存统一的风格说明、主体/比例/留白要求和逐资产提示词；一组素材共享参考和角色色。用于生成插画、透明主体、章节视觉；标题、正文、图表继续原生制作。生成图片里已有的数据刻度不能当作真实数据图表。
