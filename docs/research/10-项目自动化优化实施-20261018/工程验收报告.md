# quality-v1 项目工程验收报告

日期：2026-10-18。主线是优化可复用项目；本轮未制作新版业务PPT，未改动历史客户PPT或历史批准件。以下工程检查通过，提交用户审核；视觉质量提升仍需后续实际案例检验。

## 实施结果

E0—E6 已执行：备份 → 合同 → 图表和元素 → 阶段门禁 → Skill → 自动回归 → 证据报告。详细任务与审核点见[实施计划](实施计划.md)。

| 原有薄弱点 | 已进入正式实现的改动 | 可检查位置 |
|---|---|---|
| 内容停留在逐页文字，难核实论证 | 每页记录主张、证据、推理、限制、视觉载体、案例性质、任务专属审核问题；引用与计算可校验 | `ppt_workflow/quality.py`、`schemas/content-plan.schema.json` |
| 模板容易只有统一背景 | 语义版式声明适用载体、正文容量、最小字号、图表容量；制作阶段检查真实输入与所选布局 | `quality.validate_layouts`、`stages.py`、模板Skill参考 |
| 图表类型与表达单一 | 0.2原生横条、柱、折线真实分派；最多12类别、4系列；重点色、系列色、字体、轴范围与百分比格式 | `engine/chart_compile.cjs`、`engine/capabilities.json` |
| 元素只有文字与卡片 | 新增可编辑过程、对照、行动组件，带稳定对象ID及连接关系；容量不足明确报错 | `ppt_workflow/exhibits.py` |
| 自动检查可能掩盖设计或事实问题 | 内容、设计、工程分别判断；任务问题逐一答复，需证据；严重问题、未知项不能被平均分覆盖；返修关闭需要复查证据 | `schemas/quality-review.schema.json`、`quality.py`、`stages.py` |
| 规则升级后旧审批可能继续生效 | 代码、schema、能力清单参与审批摘要，资源或规则变化使阶段批准过期 | `stages._rules_digest` |
| 工程优化被某份PPT的大纲审批阻塞 | 总控Skill明确区分工程优化与业务制作；六阶段业务审核继续保留 | 七个独立Skill与`docs/质量升级工作流.md` |

额外修正：原生图型与声明不符会失败；百分比之差使用“百分点”；0.2表格按实际列数处理；去除引擎中的固定业务标题；Office后处理不再覆盖0.2图表的样式与数据范围。未支持图型明确拒绝，不自动退化为横条图。

这些是机制与编译能力的增强。内容需要研究者填写，模板仍需要实际选择或设计，三类元素也不是完整图形素材库；不能仅凭这些改动认定审美目标已经实现。

## 开源研究如何落地

固定提交、原文、许可与SHA256保存在[上游快照](upstreams/manifest.json)。详细映射见[开源融合记录](../ppt-workflow/docs/开源融合记录.md)。

- PPTAgent：借鉴源文件和导出结果分别审核、资源变化后复查，落实为内容计划附件与渲染绑定。
- PresentBench：借鉴逐任务问题，落实为每页专属问题、证据与unknown状态。
- PPT Master：借鉴受约束表达与显式编译边界，落实为集中能力清单、语义载体与拒绝静默转换。
- PptxGenJS：直接使用已锁定4.0.1的原生图表接口；pptx-automizer继续作为隔离实验，不引入默认依赖。

本轮是方法、合同与原创适配实现的融合，没有整体搬入外部平台，没有宣称通过上游基准，也没有复制许可存疑的Skill正文。

## 版本、备份与边界

- 0.1输入仍可读取，原统一构建入口保留旧限制；新增图表与严格质量流程显式使用0.2和quality-v1。读取兼容不表示旧批准在新规则下继续有效。
- 原始62个选定工程文件及哈希在[before清单](before/manifest.json)；七个安装Skill完整原件在installed-skills-before。当前入口另备份在before/当前工作流.md。不是整个项目的完整磁盘快照。
- 保留研究资料、历史审批、原PPT、离线依赖和失败证据。本轮没有为“清理”删除难以确定用途的文件。
- 本轮没有验证WPS/PowerPoint实时MCP、模板下载、Figma往返或生图接口；历史连接结果不能当作当前连接成功。没有新接入未验证接口。
- 编译包测试不等于Office渲染、交互编辑或设计质量认证。多系列已接入编译与合同校验；实际目标软件表现仍待验证。
- 新质量检查不会自动执行在线研究、填充证据或代替设计审阅；示例为合成合同输入，不能作为客户内容。

## 现在如何使用

在Codex中调用 `$ppt-quality-workflow`，新业务任务使用quality-v1；六阶段分别由独立Skill负责，每阶段保留真实审核。工程优化流程与命令见[质量升级工作流](../ppt-workflow/docs/质量升级工作流.md)。

后续效果验证应在本轮工程结果审核后，选一份真实案例对比：先审核内容计划，再审核统一模板与代表页，最后检查逐页内容、原生编辑性及整套视觉一致性。这个检验尚未执行，不把旧客户PPT视为本轮升级后的结果。
