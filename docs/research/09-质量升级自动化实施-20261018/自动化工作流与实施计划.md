# 高质量 PPT 自动化工作流与实施计划

日期：2026-10-18。执行目录：`ppt-workflow/runs/quality-upgrade-labor-20261018`。本轮实验代码：`ppt-workflow/experiments/quality_upgrade`。沿用既有六阶段命令与审批机制，不增加第七个专业 Skill。

## 自动化的实际分工

- 宿主智能体按各阶段 Skill 完成访谈、研究、叙事、设计、生成与视觉判断。
- 本地脚本负责文件盘点、结构与数据校验、差值计算、哈希绑定、阶段提交、原生导出、渲染和证据留存。
- 用户审核主张、视觉样页和最终效果。脚本不能代替用户审批，也不能靠返回码证明 PPT 好看。

新实验校验器没有内置模型接口，不会自动调用未配置的模型或冒充自主创作。已有 `python -m ppt_workflow skills` 是命令—Skill 注册表的单一来源。以下命令都在 `ppt-workflow` 目录执行，Python 使用本项目 `.venv/Scripts/python.exe`；Office MCP 使用 `.mcp-venv/Scripts/python.exe`。

## 1. 输入冻结与技术基线

负责：ppt-quality-workflow 调度，ppt-review 检查；需要复制修复时由 ppt-compose 执行技术副本操作。

输入：用户指定的客户 PPT、旧 spec、旧自查记录、旧逐页预览和既有需求批准件。

自动步骤：

1. 比较文件哈希，识别当前 PPT 与旧预览是否同版本。
2. 提取文字、图表/工作簿、表格、备注与来源；检查 ZIP CRC、XML、关系目标。
3. 使用已知正常文件验证目标软件，再渲染当前文件副本；禁止覆盖源文件。
4. 只针对明确缺陷产生诊断副本，并核对内容保留。打开/渲染失败保持失败；不把回退图片标为可编辑成品。

当前可复用命令：

```powershell
.\.venv\Scripts\python.exe -m ppt_workflow doctor
.\.mcp-venv\Scripts\python.exe scripts/office_mcp_client.py health runs/new-health-check
.\.venv\Scripts\python.exe experiments/quality_upgrade/baseline.py --source "runs/labor-values-20261017/美化阶段交付/客户.pptx" --out runs/new-baseline-diagnostic
```

最后一条仅处理已明确支持的 JPG MIME 异常，输出诊断副本；不能把它当通用 PPT 修复器。已生成的目录不可复用，避免混入旧证据。实际本轮结果见《执行记录》，客户文件兼容问题尚未解决。

验收：有效的新渲染绑定本次文件、页数完整、原文件哈希不变，关键对象和备注保留。技术基线没有通过时，允许独立内容研究继续；不允许给当前成品签发正式通过。

## 2. 需求承继与内容计划

负责：ppt-intake 承继已批准需求，ppt-outline 研究和改写。

本轮继续使用原批准需求：12页、5分钟、16:9、公开资料分析、主要内容原生可编辑、兼顾打印、封面姓名占位。已实际验证旧需求批准哈希，比较全部非路径字段以及两份材料的字节哈希；仅规范化材料路径。新任务保存独立承继证据，不覆盖旧任务。

新增实验产物：

- `inputs/content-outline.json`：可用既有 outline 阶段提交。
- `inputs/content-plan.json`：逐页问题、主张类型、证据、推理、限制、视觉载体、案例标签、专属审核问题。
- `R1-内容审核稿.md`：供用户阅读的12页标题串读和逐页内容卡。

自动校验包括来源/事实 ID、图表单位、强调对象、时间总和、示例标签、推导算式以及源文件/大纲哈希。语义准确性与叙事效果由宿主审阅并交用户判断。

本轮可执行入口：

```powershell
.\.venv\Scripts\python.exe experiments/quality_upgrade/quality_plan.py check --workspace runs/quality-upgrade-labor-20261018
.\.venv\Scripts\python.exe experiments/quality_upgrade/quality_plan.py status --workspace runs/quality-upgrade-labor-20261018
```

第一次提交（本轮已执行，重复执行会创建新版本）：

```powershell
.\.venv\Scripts\python.exe experiments/quality_upgrade/quality_plan.py submit-outline --workspace runs/quality-upgrade-labor-20261018
```

**审核点 G1：** 用户审核具体内容稿。通过后，宿主读取当前准确 artifact_sha256 与真实回复，使用现有 `outline --approve` 记录；不能在脚本中默认填 user-approved。内容修改先重新提交再审核。

当前 sidecar 仅为实验合同；生产 `deck.schema.json` 仍为 v0.1。实验 wrapper 负责检查 sidecar 与提交大纲的绑定，既有生产 CLI 尚不强制其字段。不能宣称全局流程已完成升级。

## 3. 模板与真实代表样页

负责：ppt-template。

输入：通过 G1 的大纲及内容计划、原模板与资源清单。先执行 `quality_plan.py status` 检查绑定，再用既有 `template --workspace ...` 查询依赖。

内容审核后，将第5、8、11页作为三种难点的代表：数据解释、价值辨析、具体行动。先继承色板/字体建立对照，再决定是否升级校园主题视觉。文字设计任务书见 `R1-设计任务书.md`，它不是已生成样页。

需要 WPS 模板时，按 ppt-template 的检索 Skill 实际浏览、选择、下载、记录来源并检查原生对象；在线模板库与桌面 COM 分开判断。不假设 Canva/Figma 的导出链路或 WPS COM 永久可用。

自动步骤：模板资源盘点 → 容量与对象映射 → 三页原生样稿 → 目标软件渲染 → 编辑性/源数据检查。图片素材共用风格说明；图片不承担数字、表格或需编辑的流程标签。

**审核点 G2：** 用户确认真实样页和整套设计规则后，记录 template 批准。未经确认不批量做全套。技术基线打不开时，可另建原生新稿，但必须明确是重建而非无损修复，并重新核对全部内容。

## 4. 三页制作、修订与审核

负责：ppt-compose → ppt-polish → ppt-review。

图表继续使用原生数据对象；默认新建路线按实际验证选择 PptxGenJS 或已验证的图表供体，不依赖本机失败过的 WPS AddChart。对图表缓存、工作簿、类别顺序、数值与注释逐一核对。

本轮发现生产事实减法检查沿用原单位、要求 scope 字符串完全相同，不能直接表达本例的“百分点”推导。D01 先放实验 sidecar；进入生产前需给百分比减法定义单位与可比性规则、增加验证，禁止通过改标签绕过绑定。

美化先解决信息主次和视觉关系，再处理字距、字号、颜色；每项保存改前/改后与原因。概念或主张变化退回 outline，风格变化退回 template。内部最多两轮定点视觉修复，无改善则上溯原因，不不断生成整页图片。

**审核点 G3：** 用户能看到三页相对原版的具体改善，并认可风格与编辑性后，再扩大到全套。生产阶段仍分别使用 compose/polish/review 提交，不把一次样页认可当成最终发布批准。

## 5. 通用能力集成

负责：各专业 Skill 更新自己的规则，总控维护路由；研发与样页效果审核分别留档。

仅集成经样页证明有效的能力：内容合同与审阅问题、图表类型/重点标注分派、语义版式与容量规则、模板和原生对象适配器、任务专属审核清单。

实施时保持旧任务可读取；新合同版本不静默放宽旧校验。现有 Skill 和阶段规则哈希变化后，受影响任务重新提交并核对，不能覆盖历史批准。新 Skill 先在项目内验证，再同步安装，备份全局版本。

不预先安装完整新平台。仅在复杂页面确有瓶颈时，固定版本试验 PPT Master；按真实输出检查编辑性、数据对象与兼容性，不能将 README 能力当本机验证。

**审核点 G4：** 新流程能够复现已认可三页的效果，非仅一次性脚本成功；针对性验证通过后再切换默认流程。

## 6. 整套与跨主题复验

负责：ppt-compose/ppt-polish 制作修订，ppt-review 独立审核。

保持12页、300秒和真实来源，对整套逐页渲染与跨页审阅；选择另一主题检验复用性，避免所有规则仅适合本劳动观案例。记录实际耗时、返工、费用及用户偏好，不预设已实现70%通过率或30%成本下降。

**审核点 G5：** 内容、设计、工程各自给结论。最终交付仍需已验证的文件打开、编辑保存、图表/工作簿一致与真实全页渲染；未知项保留。用户可以接收候选稿，但不能把它改写成全面通过。

## 工具失败与恢复

每次外部操作设置时间上限、全新输出目录、对象所有权与清理记录。PowerPoint 已有用户会话时不接管；共享 WPS 不 Quit，不要求用户清理后台进程。超时或清理不明保留隔离锁，确认归属后再恢复。

失败不靠无限重试解决：相同输入的纯重试最多一次；有新假设时记录新候选及差异。本轮已完成数种有区别的定位试验，继续技术处理需换成有明确证据的新假设或重建路径。内容审核和技术故障分别记录，避免互相伪装为已完成。
