# 从实际设计决策推动制作

本文件是本轮研究形成的实施建议，尚未修改生产引擎或安装 Skill。继续使用现有六阶段，不新增总控、不重搭接口平台。

## 各阶段应真正完成什么

| 阶段 / Skill | 实际工作 | 交接与审核重点 |
|---|---|---|
| 需求 / ppt-intake | 明确观众、使用场景、目的、时长、品牌与信息密度 | 确定是现场稿、阅读稿还是分别交付 |
| 资料大纲 / ppt-outline | 梳理主张与证据、前后逻辑，区分事实、解释与建议 | 大纲审核确认内容成立；已有content-plan写清问题、推理、限制和视觉焦点 |
| 模板 / ppt-template | 找有出处的设计参考，拆解网格、字阶、主视觉、素材与图表处理，给代表页提出有区别的构图 | 提交真实内容的代表页；看语义和构图差异，不看明暗变体数量 |
| 制作 / ppt-compose | 提前检索/预制素材，在统一视觉语言内按页实现设计；文字、关系和数据尽量原生 | 原稿对应、原始数据、视觉主次和图片裁切都成立 |
| 美化 / ppt-polish | 针对真实导图修改层级、标注、字距行距、分组、焦点和跨页节奏 | 交修改前后对照和具体理由；不要以统一颜色代替实质改稿 |
| 审核 / ppt-review | 看内容是否准确、页面是否有力、整套是否连贯，并保留必要编辑检查 | 具体问题对应页面及对象；用户审美决定单独记录 |

## 每页设计要回答的七个问题

1. 观众读完这一页应该理解什么？使用既有 question / claim，不重复造字段。
2. 哪个证据或对象最重要？使用 exhibit.focus / dominant_evidence。
3. 信息之间是什么关系？沿用已有 relationship；尚不支持的关系先设计原生样页，不硬改成已支持的类型。
4. 观众先看哪里，再看哪里？使用 reading_order，让实际位置、大小和对比与顺序相符。
5. 图形为什么采用这个构图？使用 layout_reason 与逐页视觉计划，记录简短可判断的理由。
6. 哪些细节应在图上，哪些进讲稿？正文调整或拆页仍走大纲审核，不能由排版器偷偷摘要。
7. 用真实文字、图片和数据渲染后，第一眼实际看到了什么？记录截图上的观察及修改。

这些首先是设计工作，不要求新增七份文件或七个命令。原有资料与布局合同没有的内容可先写入page-visual-plan.md，等真正需要程序读取时再扩展结构。

## 参考与素材如何利用

参考页按表达任务整理：证据主导、对照、系统机制、流程、空间场景、密集分析、行动收束。每个条目保存原作者链接、使用场景、学到的构图原则和限制。作者案例用于研究；只有明确获得相应使用权的文件才作为可复用资产入库。

从参考中学习四类决策：信息怎样分组，面积和字阶怎样分配，图片怎样裁切/标注，跨页怎样延续。避免只提取几个颜色与圆角。

素材准备继续在任务目录内提前完成。检索条件加入该页语义、视觉角色、必须保留的主体、画幅与标注要求；关键页比较候选时实际看图。imagegen适合制作缺少的概念/场景资产，需要在统一画风下保留主体与留白；重要数据、文字和关系不烧入位图。

## 第一轮应该怎么做

先从原客户PPT第04、06、08页制作三种实质改稿，分别验证数据主导、分析框架和密集对照。保留原文件，只在新任务目录生成候选。

顺序如下：

1. **材料复核**：读取原页、对应大纲、来源和讲稿，确认本轮不改变哪些事实；需要改措辞/拆页的部分列为提案。
2. **构图草案**：用同一实际内容提出两种不同组织方式，如数据与解释边界的组合、三方面观察框架、表格与案例路径。不是每页都机械产出两稿，关键且有真实取舍的页才比较。
3. **素材和原生准备**：优先利用原证据和原生图形，只为清晰表达补充有用的图片/标注。能力不足先手工建立可编辑样页，记录再复用；无需先开发一整套通用命令。
4. **实际制作**：沿用已确定的视觉语言，调整主视觉比例、标题宽度、局部标注和分组，导出真实页面。
5. **具体改稿**：每页回答最重要的一个问题：主张是否更清楚、关系是否更直观、视觉是否更有主次。指出画面哪里应改并执行，而不是只生成一份问题清单。
6. **提交代表页审核**：展示原稿与新稿，以及保留的事实和改动理由。用户认可设计方向之后再总结可复用规则与批量推广。

## 三个必要审核点

| 审核点 | 要看的实际东西 | 通过依据 |
|---|---|---|
| 内容设计 | 真实文案、证据和构图草案 | 要表达的判断成立，图形关系与资料相符 |
| 代表页效果 | 三张实际可编辑页面及前后对照 | 页面有明显主次，图文共同表达意思，视觉有实质改善 |
| 整套应用 | 任务实际成品与接触表 | 系统统一、构图服务内容、节奏自然，复杂页同样可用 |

可借用Duarte的Glance Test检查能否很快找到主旨；“三秒”是该方法的实践提示，不作为所有科研图表或阅读稿必须达到的客观阈值。[来源](https://www.duarte.com/resources/guides-tools/the-glance-test/)

保留必要的数据、溢出、图片身份、原生对象及实际导图检查。将主要迭代精力用于设计；既不省略真实效果审核，也不以测试数量来证明成品美观。

## 值得迁移与暂缓事项

优先迁移：显式页面设计→原生实现的交接、主证据与阅读顺序实际驱动版面、基于真实截图的具体改稿、通过用户审核的构图经验。

暂缓：继续补明暗主题、为避免单调而机械轮换布局、大批生成示意数据样件、未经实际设计验证就扩大配方数量、将模型审美总分当作自动交付批准。
