# 高质量 PPT 取决于怎样表达内容

上一轮把同一组几何结构分别改成明亮、深色，验证了主题继承，却不能证明设计质量提高。用户的纠正成立。23号研究已经提出“结构丰富不能靠换颜色得到”；后续实现了若干配方，但对实际设计决策和成品改稿投入不足，不能再次把已有原则包装成新发现。

以下质量框架是本轮对专业方法、原始案例和项目实现的综合判断，不是行业统一评分标准。

## 1. 先确定成品是给谁、怎样使用

现场讲述、科研答辩、领导阅读和产品发布需要不同的信息密度、图形复杂度和节奏。先确定观众需要理解什么、相信什么或决定什么，再确定详略。Duarte 明确区分有讲者带领的投影页面与读者自行阅读的 Slidedoc，制作上不能假设两种用途共用相同密度。[来源：Duarte](https://www.duarte.com/blog/the-slides-you-deliver-versus-the-slidedoc-you-leave-behind/)

对本项目的含义：需求阶段要让“现场展示/自行阅读/两套输出”实际影响后续大纲与版面。当前所谓高级、简洁或丰富，都必须放在使用场景里判断。商务分析可以信息密集且精致，发布展示可以用很少的字建立冲击力，不能全部做成同一种宣传海报。

## 2. 每页首先有值得表达的主张

资料需要经过选择、解释和组织。“研究背景”“问题分析”是栏目，尚未说明观众应获得什么认识。科研/证据型页面可以学习 Assertion-Evidence：先写清完整的关键信息，再让可视化证据支持它；口头解释与次要细节进入讲稿。该方法的证据与适用讨论主要针对技术演示，不能据此要求所有封面、章节或阅读稿都只有一句话。[来源：Michael Alley 的教程](https://www.craftscicom.org/ae_tutorial.html)

对本项目的含义：大纲不能止步于标题、正文和“配一张图”。还要回答：这一页解决什么问题；哪些材料支持主张；哪些只是背景；下一页为什么出现。优先修正文案的空泛、重复和证据不足，再讨论画面。

## 3. 让内容关系变成可见结构

专业页面会把比较、变化、组成、流程、空间、因果和从属关系组织成图形。BrightCarbon 的公开方法将对象识别与关系识别放在视觉制作之前，构图由对象之间的关系推动。[来源：BrightCarbon](https://www.brightcarbon.com/blog/how-to-create-visual-presentations-and-elearning/)

我们可以据此建立设计判断，而不是机械图型轮换：

| 内容需要观众理解什么 | 优先探索的表达 | 需要避免的误用 |
|---|---|---|
| 两种方案差在哪 | 同口径对照、共同尺度、差异标注 | 给每个方案画一样的卡片却没有比较轴 |
| 发生了怎样的变化 | 趋势、前后对照、阶段演进 | 用无序项目伪造趋势 |
| 系统怎样运作 | 对象、连接、输入输出与反馈 | 只有若干矩形和单向箭头 |
| 一件事为何发生 | 有依据的因果路径与条件 | 把相关性连成因果箭头 |
| 证据具体在哪里 | 原始照片/界面/实验图与局部标注 | 用同主题的漂亮插画代替真实证据 |
| 应采取什么行动 | 行动、责任、顺序与结果的对应 | 把若干抽象口号并列 |

表格是项目建议，不表示本机编译器已实现所有表达。

## 4. 页面要有视觉主次与可追随的视线

观众应该先看主张或关键证据，再看解释，最后按需读来源。可用手段包括面积、字号、字重、位置、对比、留白和邻近关系。留白承担分组、强调和节奏功能，空出来一大块本身不构成设计。BrightCarbon 的课程材料用尺寸与重要性、色彩强调和邻近分组解释这种层级。[来源：课程材料第15—20页](https://www.brightcarbon.com/wp/wp-content/uploads/2025/10/BrightCarbon-Communicate-Effectively-with-Dynamic-Visual-PowerPoint-Summary-01-Learning-2025.pdf)

对本项目的含义：齐整只是底线。固定“顶部标题＋一句概述＋左图右文”，即使不溢出、颜色一致，也可能缺少主视觉、语义关系与设计张力。图文不必平均分面积；关键图应取得足够空间，解释应贴近需要解释的部位。

中文需要特别注意标题的语义断行、段落节奏、标点避头尾、数字与单位、字号和字重的对比。已有字宽测量适合守住容量，不应替代排版判断。也不应把字号层级全部锁成固定的30/20/19pt后期待所有任务都精致。

## 5. 图表需要明确的阅读任务

同一组数据，突出某个系列和突出某个时点，会让观众看到不同重点。SWD 的原始三稿恰好展示了这种区别：弱化不必要元素之后，再通过局部强调引导注意。[来源与图表原稿：SWD](https://www.storytellingwithdata.com/blog/two-tips-for-better-graphs)

对本项目的含义：先问这张图是为了比较、发现拐点、看差距还是解释构成，再决定排序、图型、标签与注释。进一步的视觉改进应围绕直接标签、关键区域、基准与差值，而不只调整柱宽和颜色。复杂分析需要保留必要上下文，不能为“清爽”删除支撑判断的数据。

## 6. 素材要完成页面的具体任务

图片可以承担证据、对象说明、场景或概念隐喻；图表、示意图和结构化数字同样属于视觉表达。图文关系成立时，标注、裁切和构图会帮助观众理解内容。高分辨率、检索命中、画风统一都只是必要条件中的一部分。

素材整理应记录“为什么这一页要它、主体在哪里、哪些细节必须保留、准备怎样标注”，从而指导检索和制作。已有 imagegen 可用于场景、插画、物体和概念素材，原生文字与真实图表仍独立制作。可编辑的关键是文字、数据和逻辑能被修改，不能以整页截图省去页面设计。

## 7. 一致性、丰富性与整体节奏需要同时成立

一致性来自字体系统、间距、色彩角色、图片处理、图表语法和标注方式。构图可以随内容改变：核心结论页可以突出一个证据，分析页可以更密，过程页可以分步解释，结尾明确行动。

DeepSlides 将跨页一致与跨页多样作为整套设计问题，并将页面设计与实现分离。这为自动化提供了参考方法；作者的实验结果还不能证明它在我们的中文任务与本机环境中一定更优。[来源：论文第3节](https://arxiv.org/html/2605.26451v1#S3)

## 当前项目的具体差距

| 已有基础 | 仍然存在的断点 | 影响 |
|---|---|---|
| content-plan 的 exhibit.intent / carrier / focus / annotation，三维质量审核 | 最近的样件主要证明模块能组装，缺少同一真实业务页的设计比较 | 工程通路完整，实际表达质量没有相应证据 |
| production brief 支持 reading_order / dominant_evidence / layout_reason | brief_composer 没有读取这些字段来决定几何与视觉权重 | 设计意图停留在文字记录里 |
| 原生关系图已有 process / hierarchy / comparison | 每类只有受限构图，许多真实空间/反馈/多层关系尚未表达 | 容易把复杂意思压成普通方框 |
| layout_capacity 可测量中文并保留全部正文 | 优先比较页数和容量，无法判断哪种构图更有表现力 | “放得下”容易被当作“排得好” |
| 封面、章节与结尾能生成原生对象 | 封面总是相近的文档图形，主体与主题之间联系较弱 | 品牌和题材辨识度不足 |
| 素材已有检索、来源、裁切、风格记录 | 选中的图片未必就是最强证据，部分只承担泛主题装饰 | 图片漂亮，页面依然没有说服力 |
| PowerPoint 实际导图、对象与工作簿检查 | 检查可读性多，对主次、关系、节奏的实质改稿少 | 正常输出被过早视为质量成果 |

上述判断针对当前所读的生成路径与最近样件，不是对项目所有历史能力的否定。现有内容计划、素材包和审核协议应继续使用，避免又造一套平行工作流。

## 建议优先级

P0：选取一份已有真实任务的三张代表页，结合有出处的设计参考做真正的构图改稿；审核主张、图形关系、视觉主次和图文整合。停止用文件宽度比较、明暗变体或“又多了几种布局”作为主要质量证明。

P1：把通过审核的设计意图真正传到制作层。先连通既有 reading_order / dominant_evidence / exhibit.focus，而不是先增加大量字段；让必要的区域、字号和主视觉权重能按页设计。

P2：从已获认可的实际页面提炼可复用配方、模板与素材处理规则。每项积累都保留适用内容、反例与原生实现。届时再决定是否迁移 DeepSlides 的局部机制。
