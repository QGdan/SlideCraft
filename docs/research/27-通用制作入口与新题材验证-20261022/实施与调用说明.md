# 通用制作入口已接通

2026-10-22。本轮把前三批能力收成brief-compose，归ppt-compose。主要改善是新主题不必再写专用拼页脚本：输入详细大纲、已封存素材、设计系统和逐页布局选择，直接生成原生PPT、正文/素材对象映射及composition.json交接件。

模板Skill负责选择页面布局和小标题；正文通过body_index引用大纲原文，不再复制第二份。制作保留全部页ID、主张、事实与来源。多必需视觉、缺素材、超容量、颜色或原生片段不匹配时明确停止，不悄悄删文或换方案。

## 当前能做什么

- 图片/图标页：已有图旁布局、上图下文及新增图右文左；实际正文测量后排入。
- 原生关系页：直接使用包内已准备的步骤、层级或同维度对照，保留文字、分组和连接符。
- 原生图表页：保留数据、嵌入工作簿与事实模板；可使用已有趋势注释片段。

本入口暂限定每页一个主要必需视觉、常规宽屏、微软雅黑和同一背景角色色。关系/图表页正文作为一行概述；长解释、复杂表格、任意导入模板和通用封面继续用专门路线。此范围是可复用制作能力，不是所有PPT布局的自动求解器。

## 直接调用

进入ppt-workflow，在项目虚拟环境中运行：

```powershell
python -m ppt_workflow brief-compose --input examples/brief-composition-campus.json --out runs/新的任务目录/composed --node D:/node/node.exe
```

该示例指向本轮已经准备好的真实输入，可用于重现样例；新题材需替换其大纲、素材包、设计系统和页面选择，不能把示意数据当业务事实。输出目录必须是runs下的新目录。

自然语言调用可写：

> 使用PPT六阶段流程。先完善并审核逐页正文与素材需求，再准备任务素材包和真实模板样页。模板确认后，支持的图片、关系、图表页使用brief-compose制作，保留正文与素材对象映射；完成后逐页美化与审核。

字段、阶段职责和使用边界见[从详细大纲到通用制作](../ppt-workflow/docs/从详细大纲到通用制作.md)。命令不代替需求访谈、内容研究、审美判断或用户批准，composition.json提交原compose阶段时仍检查上游交接。
