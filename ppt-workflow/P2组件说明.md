# P2 内容、主题与版式接口

本阶段提供可追溯的原生生成基础。成品风格尚待 G2 用户审核，正式 CLI、自动修订和新版 Skill 在 P3 实现。

## 事实与来源

`examples/demo-report-v1.json` 是明确标注的示意源文件。它不是旧交付包的替换文件。人工汇总 40 分钟，自动汇总 1 分钟，节省 39 分钟，耗时比 40 倍，均不含人工审核。

deck 合同保留 0.1 版本，新增可选字段以兼容 P0/P1 用例。P2 内容检查则要求实际使用的事实具有 `locator`、`period`、`metric`。`scope` 记录统计口径，`is_demo` 记录示意性质。

公式只支持显式声明的两项减法和除法，按同单位、同口径、同时间核算。派生值由公式校验，禁止把两个不同统计范围相除。本阶段示意源使用 JSON Pointer 定位并核对原记录；外部网页、PDF 原文是否确实支持结论仍需人工研究，不自动宣称来源真实性已验证。

数值文本用 `text_template` 引用事实，例如 `汇总用时：{fact:before}`，实际文本必须等于按事实展开的结果。图表每个数据点带 `fact_ids`，表格每个涉及事实的单元格也带绑定。对中文“数字＋分钟/秒/倍”的未绑定说法报错；这不是所有自然语言数值的完整识别器。

## 主题

| 主题 | 背景 | 正文 | 强调色 | 适用的设计方向 |
|---|---|---|---|---|
| academic | 白色 | 深蓝 | 深青 | 学术与教研汇报 |
| business | 暖白 | 深灰蓝 | 蓝色 | 业务方案讨论 |
| technical | 深蓝灰 | 近白 | 明青 | 技术方案展示 |

三套主题共用版式，以便比较同内容下的阅读效果。使用微软雅黑。封面 40pt、页标题 32pt、正文 18–24pt、图表标签 16pt、表格 20pt、来源 11pt。可通过 `demo_deck(theme, overrides={"accent": "803A65", "font": "..."})` 覆盖品牌色或字体；覆盖后必须重新检查、渲染和审核。字号目前由版式定义，不宣称任意字号覆盖已经支持。

## 十类可复用布局

`ppt_workflow.design.compose_page` 接收主题、编号、版式、标题、结论、内容参数、事实字典、来源 ID、可见披露和讲稿。示例文字在 `DEMO_CONTENT` 中，与版式计算分离。替换内容不会自动携带示例的业务文字或来源。

| layout | 内容参数 | 初期约束 |
|---|---|---|
| cover | subtitle、context | 一个标题、一个副标题、汇报背景 |
| takeaway | headline、body | 一个主结论、短解释 |
| kpi | metrics、body | 恰好三个事实 ID / 标签对 |
| comparison | columns | 恰好两组标题 / 正文 / 事实文本模板 |
| chart_takeaway | chart_title、chart、callout、label、body | 单个原生图表与一个事实强调 |
| process | steps、body | 恰好四步，步骤标签与说明 |
| timeline | milestones | 恰好四个阶段，各带时间 / 标题 / 说明 |
| table | table、body | 三列、四行数据，事实单元格绑定 |
| divider | section、body | 章节编号、标题和一句解释 |
| closing | headline、body、request | 审批事项与下一步要求 |

超出初期项目数量时拒绝编译，防止默默丢项。长文本仍需 QA 与实际渲染，无法依靠固定模板保证任意文字都放得下。更多行列或复杂分组可使用经过合同检查的自定义 scene，自动分页不在本阶段承诺内。

scene 自己保存坐标、角色与逻辑 `group_id`。流程框、标签和连接线都是原生可编辑对象；逻辑组当前保存在 spec/map 中，输出没有承诺 PowerPoint 的物理组合功能。生成器通过公开 `objectName` 设置稳定名称，不访问 `_slideObjects`。检查器建立 spec ID 到实际 shape ID 的映射，用于字号角色和问题定位。

## 图表与导出

本阶段完整渲染与编辑探针覆盖二维横向条形图。生成器包含柱形、折线和饼图分支，但尚未逐种完成真实 Office 视觉验收；散点图拒绝构建。图表类别、系列名、数值缓存与内嵌 XLSX 的公式引用均核对。工作簿引用当前只支持单列范围或单个单元格，多层类别缓存报告失败，不能当作已验证。

PptxGenJS 4.0.1 的两项已复现导出问题由 `export_fix.py` 修正：不存在的次级母版声明、二维图表额外系列轴引用。原始 `raw.pptx`、修正日志和最终 hash 均保留。不修正未知轴错误，不改数值、文本或布局，也不降低 QA 阈值。

图片只在 scene 显式允许栅格时使用。`assets.register_asset` 登记路径、SHA256、像素尺寸、source ID 和明确的许可/授权说明，图片元素必须通过 `asset_id` 与登记项关联。构建前检查文件和来源引用，构建后检查内嵌图片字节是否一致。本轮成品示例没有栅格对象，注册路径和篡改检测用独立测试样本验收。许可文字是使用者的声明，工具不代替法律判断；交付资产打包将在 P3/P5 收敛。

## 重建与检查

从项目目录运行，输出目录必须全新：

```powershell
& .venv/Scripts/python.exe scripts/build_p2.py --out runs/p2-rebuild-new
& .venv/Scripts/python.exe scripts/render_p2.py runs/p2-rebuild-new
& .venv/Scripts/python.exe scripts/bind_p2_render.py runs/p2-rebuild-new
& .venv/Scripts/python.exe -m unittest discover -s tests -v
```

`render_p2.py` 顺序运行 Office，不接管已有用户 PowerPoint 会话。该机器已安装锁定依赖。`setup_p2.py` 是一次性的阶段迁移记录，不属于每次重建命令。

QA 的 `unverified` 仍可能来自完整 OOXML Schema 未运行、文字布局估算、表格继承与图表标签几何未全部建模。这些项目保留未知标志，真实 PNG 审阅作为另外的证据。用户阶段审核与自动检查状态独立。
