# PPT 美化与润色

按项目docs/视觉优先的制作约定.md执行：主要精力用于内容、选材、模板和逐页视觉打磨。保留必要的文件/数据与实际页面检查，普通排版不反复跑大规模工程测试；页面仅保留必要的数据、来源和许可标注，工程声明留在内部记录。阶段审核优先展示真实效果。

大纲与任务素材包按项目docs/大纲驱动与任务素材包.md冻结后再美化。优先修复逐页具体问题，不在美化时临时换图、改论证或另选整套模板。必要换素材先更新包、来源/用途记录和受影响审核，再制作新稿。

在线素材已入页时按项目docs/在线素材检索与入页.md检查照片焦点、裁切、透明边缘、角色色和有效PPI；图片须帮助本页内容表达。调整位置不能丢失署名或来源；换素材重新走检索选择与prepare/place记录，不用远程预览URL直接充当已下载素材。

先审查信息设计：主张是否有对应视觉证据、图表能否看出重点、关系能否通过结构表达、跨页构图是否合理。为每个实质问题记录原状态、目标及修改依据；只有脚注字号、近似颜色和备注恢复时，明确属于排版修正，不声称完成信息设计升级。主张、数据或解释变化仍退回对应上游；不强行新增装饰或改变已批准风格。

项目位置见相邻 runtime.json；在该项目虚拟环境运行 `python -m ppt_workflow`。本 Skill 可单独执行本专业任务；使用持久化阶段命令时仍需有效的上游交接件。

负责“把已做好的 PPT 打磨好”，入口命令为 `polish`。读取获批的 composition.json、模板和原生成品；先看全套接触表，再看重点页与全尺寸图。

场景图与原生内容混合时，按[分层视觉润色](references/layered-visuals.md)核对焦点、对比、留白和跨页节奏。

做版式对照时固定文字、数据、顺序与原图，只改构图、字级和裁切；分别说明适合总览还是逐步讲解。按项目docs/版式与素材设计方法.md检查留白、分组和素材风格，避免把“大图更多”当作结论。

## 打磨方法

数据页按项目docs/原生图表视觉配方.md检查重点颜色、标签精度、图例和结论位置；只改变呈现，不改值、类别/系列顺序或比较口径。结论数字用事实模板，差值仍核对公式和单位。不能为好看裁切零基线，也不能用图表截图绕过原生数据检查。

选用项目插画/模块时按docs/插画与原生模块库.md查看真实预览与容量，检查人物是否帮助表达、黑色轮廓是否适合背景、标题与说明是否靠近分组。修订模块实际对象，不能用截图替换原生文字和关系线；预览只作选型参考，正式页面需再次导图检查。

核对制作前图表与素材准备清单.md及逐页图文结合：文字与视觉内容共同解释本页结论，避免纯段落页和图标凑数。若图表或图片缺失，先补准备、来源与真实预览再排版，不将图库里的示意图充作本任务数据。

依绑定项目 `docs/页内排版与素材调用工作流.md` 检查每页文字、图表、图片的区域分配和阅读顺序，不能把页面方向或步骤横竖排列当成整项布局优化。查阅page-visual-plan.md与实际检索记录；补图或换图先检索并查看候选，维护来源与放置记录。优先解决内容主次、分组、对齐、留白和证据可读性，依据渲染判断素材是否帮助表达。

先查跨页一致性：背景、字体层级、页眉页脚、页码、间距和插画材质是否一致。再优化信息层级、对齐、空白、数字强调、图表标签与配色、表格密度和流程阅读顺序。每处修改关联页/element ID 与具体原因，不通过加装饰掩盖信息不清楚。

可精简冗余正文和改善措辞，但不改事实、口径、计算结果、图表/表格数据、流程语义和已批准的逐页主张。核心结构或主张需要改变时退回 ppt-outline / ppt-compose，品牌、模板、字体系统和背景变更退回 ppt-template。

需要新插画时使用可用 imagegen Skill，沿用模板的色彩、材质、光源和留白；正确登记新素材。需要编辑矢量图层或 Figma 元素时加载对应插件 Skill，在实际图层操作并截图检查。图像生成器未公开模型 ID 时不要声称指定了 Image 2；PNG 不能自动无损拆成原生图层。

## 输出与交接

可按需求增加转场或动画，但先确认最终播放软件和交付格式。粒子、3D 或网页交互属于可选增强，需单独验证导出；HTML/PDF 的视觉效果不能代替原生 PPTX 编辑验收。优先解决静态页面的一致性、图表表达和阅读节奏，再审核动态效果。

polish-report.json 包含 deck、deck_spec（改后实际文件）、visual_notes、copy_notes、changes。changes 为 [{"element_id":"…","change":"具体修改","reason":"对应问题"}]；确实无需修改时可为空，但说明查看过哪些页面以及为什么保留。

保持事实和主张可追溯，输出原生 PPT 与 spec 相符。用 `polish --workspace <任务目录> --input polish-report.json` 提交，审核后交给 ppt-review。自查用于定位和修复，不等于最后的审核结论；未看到截图不要写“已美化完成”。
