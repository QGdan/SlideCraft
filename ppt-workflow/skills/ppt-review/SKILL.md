# PPT 效果审核

素材与构图按项目docs/素材风格与图像叙事.md核对共享风格、任务角色、实际提示词/参考与入页裁切；区分检索计划、真实调用和已选素材。查看图片叙事的上下区域与跨页一致性，趋势注释须对应正确月份/事实，不把普通说明带当数据点连接。

按项目docs/视觉优先的制作约定.md执行：主要精力用于内容、选材、模板和逐页视觉打磨。保留必要的文件/数据与实际页面检查，普通排版不反复跑大规模工程测试；页面仅保留必要的数据、来源和许可标注，工程声明留在内部记录。阶段审核优先展示真实效果。

按项目docs/大纲驱动与任务素材包.md核对详细大纲正文与讲述意图是否落地、必需视觉任务是否实际实现、素材包与页对象是否对应，查看原图/原生图表源及真实导图。存在素材文件不代表选材合适，字段齐全不代表大纲有深度。素材变化、来源变化与数据变化分别按责任阶段退回，不把自动化命令结果当作人工审核通过。

按项目docs/在线素材检索与入页.md核对实际results/preparation/placement记录、来源许可、可见署名和图片与文字主张的关系，检查实际目标软件渲染。在线库集合规模不等于本地素材量；partial/timeout不算成功接入；检索候选未经选择、下载或渲染不能记为已使用。检查重叠与PPI警告的处理证据。

项目位置见相邻 runtime.json；在该项目虚拟环境运行 `python -m ppt_workflow`。本 Skill 可单独执行本专业任务；使用持久化阶段命令时仍需有效的上游交接件。

负责审核结果与问题定位，入口命令为 `review`；底层 qa / deliver / benchmark 归本 Skill 所有。先读已批准的需求、大纲、模板和美化后成品，而不是只读制作者的总结。

视觉对照先核对全部正文与原始素材相同，再看阅读顺序、密度及裁切代价；真实观察与用户偏好分开记录，不自动给出美观分数。

## 审核

图表配方按项目docs/原生图表视觉配方.md核对来源/计算、标签精度、零基线、图例和原生工作簿；能导图不表示数据可编辑。WPS转存后必须读chart-preservation.json：丢工作簿的副本不得交付，uncompared也不表示数据通过。遇到折线类型字段unknown保留未验证结论，不删除错误或用截图掩盖。保留原始生产PPT作为对照。

插画与模块按项目docs/插画与原生模块库.md核对：图片出处与CC0记录、人物适用语境、模块elements来源、实际原生对象、日期/步骤/产出是否对应任务资料。module-search预览和module-prepare成功不能代替正式页面审核；没有完成原生编辑往返时区分对象存在检查与实际编辑保存检查。

常规Python导图失败且worker清理证据完整时，可按项目docs/Office直接导图与连接恢复.md在终端直接运行scripts/render_direct.ps1，核对本次render-manifest.json与逐页真实PNG，再做视觉审核。直接导图通过不等于原Python启动链已修复，也不替代逐页观察。清理不确定或已有用户会话时遵守隔离锁，不自行强制结束Office。

按绑定项目 `docs/页内排版与素材调用工作流.md` 核对逐页内容布局和素材使用。查看制作前图表与素材准备清单.md、page-visual-plan.md、实际检索结果及导图；每页须有文字和相关视觉内容，原生图表或关系图无需另加照片。纯文字页、装饰图标凑数及缺少数据依据的图表退回处理。图片/图标须有候选取舍、来源及放置记录，自制图表/图形须有源文件和数据/语义依据。检索或生成成功不代表排版美观；核对图文关系、图表主次、对齐、留白、裁切与可读性，不以横竖方向代替布局判断。

quality-v1任务按[任务专属三维审核](references/task-review.md)分别检查内容、设计和工程，并提交quality_review附件。由内容计划的问题生成待回答清单，真实看过源稿与最终渲染后才填写答案和证据。严重错误、未验证项和未解决问题不能被平均分覆盖。返修写明页/对象、责任阶段、建议和复查证据；审核本身不代为修改事实或美化。

运行静态 QA、事实/公式和原生对象检查，绑定本次 PPT、spec、渲染清单与逐页图片哈希。查看接触表检查跨页节奏，再逐页查看全尺寸图，重点检查标题换行、越界、重叠、对齐、数据标签、中文字体、图像裁切和整套一致性。

内容审核核对来源、数值、单位、时间、统计口径和示意标记。将必须修的问题定位到 slide/element，并给出可执行的返修建议。制作未按大纲或模板执行，退回 ppt-compose；版式与措辞打磨退回 ppt-polish；事实或模板本身有问题，退回相应上游 Skill 后重审下游。不要在审核记录里悄悄替作者修改文件。

使用宿主图像审阅时保存实际逐页观察与跨页、内容判断；使用视觉 API 前预留额度，初次与失败共三次。视觉检查不能替代没有执行的 OOXML schema 校验、交互编辑往返或其他未覆盖检查，零 error 也不等于全面通过。

图片与原生内容混合的成品，另按[分层视觉审核](references/layered-visuals.md)检查裁切、媒体登记、原生编辑边界与深色变体。

## 输出与正式交付

review-report.json 包含 qa_report、automated_qa、render_manifest、visual_review、assessment、decision。文件指向本次真实检查记录，visual_review 的 binding 必须对应 deck/spec、原自动 QA 和完整渲染图。decision 与真实检查一致：failed / unverified / needs_review / passed，不用平均分覆盖严重缺陷。

用 `review --workspace <任务目录> --input review-report.json` 提交。用户批准审核报告只表示接受该阶段的判断；若判断仍为 unverified，并不授权正式发布。

底层 deliver 仅允许 ready + QA passed、零未解决 warning/unknown 且视觉记录有效时放行。当前示例仍有部分自动检查 unknown，保留候选稿状态，不删除 unknown 或伪造 passed。benchmark 只报告已测本地指标，不冒充外部引擎对照。底层命令与视觉记录格式见 references/engine-cli.md。
