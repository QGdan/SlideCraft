# 内容关系与原生构图

本能力借鉴23号源码调研中的关系建模、可执行配方和分模块思想，自主实现；不依赖外部Skill或Canva。原有素材包、来源和阶段审核继续沿用。

## 工作分工

- **ppt-outline** 在详细production-brief的diagram视觉任务中描述relationship：明确kind、来源依据basis、source_refs、nodes、edges。comparison还需dimensions和两边对应cells。这里不写坐标。
- **ppt-template** 按内容关系、实际文字量和可用版面决定是否采用配方；流程不必强制改成时间线，层级也不能当作步骤。
- **ppt-compose** 通过relationship-prepare生成普通scene elements，再合并到本页，用editorial-build生成原生PPT。实际预览确认后，request和elements可按source文件连同preview进入原有material-pack。
- **ppt-review** 看实际PPT导图，核对主次、文字、连接关系和可编辑对象。PPT文件中存在形状不等于页面表达已经通过审核。

## 当前配方

| kind | 实际支持 | 不支持时怎么处理 |
|---|---|---|
| process | 2–4个有序步骤，可带body和output；顺序边与节点排列一致 | 分支或更长流程换结构或拆页，不丢步骤 |
| hierarchy | 单个根节点和最多4个子节点，可带子节点解释 | 多层关系先拆分；根节点长说明和边标签换布局 |
| comparison | 两个方案，共用2–4个维度且两侧值齐全；没有顺序箭头 | 多方案或不对应的内容换配方，不拼凑维度 |

这些用于定性关系，不把文字中的数字自动变成按值缩放的图表。真实数据图表继续用chart-prepare及事实表。普通原生节点组不是SmartArt数据部件。

示例请求位于examples/relationship-process.json、relationship-hierarchy.json、relationship-comparison.json。几何由request的rect和当前配方确定；第一批需要至少10×3.8英寸区域，含步骤产出通常需要更高区域。使用Microsoft YaHei实际字体度量做保守容量估算，最终以PowerPoint导图为准。

## 命令

在ppt-workflow目录内，使用本项目虚拟环境：

```powershell
.\.venv\Scripts\python.exe -m ppt_workflow relationship-prepare --input examples/relationship-process.json --out runs/本次任务/图形准备
```

读取输出elements.json，将elements合并到相应slide，保持source_refs已在该页和任务sources登记、ID不冲突。调色可使用同名语义色，不能任意删掉节点或说明以适应模板。输出的group_id由editorial-build写成真实原生组合；connection由同一构建链写为p:cxnSp，并绑定到真实形状ID。

```powershell
.\.venv\Scripts\python.exe -m ppt_workflow editorial-build --input runs/本次任务/deck-spec.json --design runs/本次任务/design-system.json --node D:/node/node.exe --out runs/本次任务/build
```

保留整个分组的原生对象，允许在PPT中取消组合后编辑。当前是图形片段整体语义分组，节点文字与背景并未另建嵌套组合。连接符跟随背景形状，移动某个背景时其单独文本不会自动随动；整体移动请移动分组。

## 出口边界

editorial-build不再把diagram/smartart画成占位矩形；必须先展开成实际elements，或明确使用已支持的Office路径。现有Office流程与SmartArt能力按原记录保留，不能因新增原生节点就声称任意SmartArt已支持。

新增shape_kind可选rect、roundRect、ellipse、diamond、chevron、hexagon、parallelogram。原有shape无该字段时仍为rect。connection仅用于0.2的line，端点必须为本页同一语义组中的原生shape，连接点0/1/2/3分别为上/左/下/右。当前配方已导图的是直线和扇出关系；折线几何是可声明的底层选项，未作为本批配方验证范围。

原有production-brief/1仍可用；新字段可选，有relationship时做结构/来源验证。它不替代人工核对原文是否真的存在该关系。模板、美化阶段不擅自改关系或事实。
