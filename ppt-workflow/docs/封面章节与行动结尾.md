# 原生封面、章节与行动结尾

2026-10-22。当前编辑式风格家族增加cover、divider、closing三种可复用整页构图，和图片、关系、图表页共用字体、角色色与边距。不是将整页位图作为模板，文字与图形均为原生对象。

## 阶段分工

- **大纲**定义封面/章节/结尾的页面角色，写完整title、body_blocks与导航标签；行动项来源于已有内容，不由模板编写器新增。visuals中的editorial_frame是内容角色与标签，只有kind/kicker/footer/section_label或headings，没有色彩、字体和几何。
- **模板**使用frame-catalog查看实际预览，结合正文、关系、数据代表页确定整套视觉系统。主题字体/角色色放design-system，与大纲文字分离。当前只有这一套固定构图家族，其他模板需实际适配。
- **制作**用frame-prepare读取该页原文、内容角色与已选主题，输出原生整页片段。连同实际预览进入material-pack，随后brief-compose拼成整套。
- **美化/审核**查看封面建立主题、章节制造停顿、内容页解释与结尾落地行动之间的节奏，不能只分别看三张漂亮空壳。正式阶段提交仍检查已经批准的大纲和模板。

大纲内容改变时更新上游，不能只改准备片段冒充原文；换色板无需重新写业务文案，但应按选定主题重新准备片段与预览。

## 调用

在ppt-workflow的虚拟环境中：

```powershell
python -m ppt_workflow frame-catalog
python -m ppt_workflow frame-prepare --input examples/frame-cover.json --out runs/新任务/封面
python -m ppt_workflow frame-prepare --input examples/frame-divider.json --out runs/新任务/章节
python -m ppt_workflow frame-prepare --input examples/frame-closing.json --out runs/新任务/结尾
```

frame-catalog归ppt-template，frame-prepare归ppt-compose。输出使用runs下新目录；示例是本轮真实内容，可重现样件，新题材需使用自己的原文和source_refs。

`editorial-frame-request/1`字段为slide_id、element_id、theme、frame、content、source_refs。theme是font与colors；当前微软雅黑，至少包含background/ink/accent/muted/surface/line六个角色色。content为 `{title,body_blocks}`，必须与该页大纲原文一致。

frame结构：

```json
{"kind":"cover","kicker":"方案汇报","footer":"来源：自撰方案。"}
```

```json
{"kind":"divider","kicker":"组织方式","footer":"来源：自撰方案。","section_label":"01"}
```

```json
{"kind":"closing","kicker":"下一步安排","footer":"来源：自撰建议。","headings":["明确范围","组织协作","保留记录"]}
```

closing的headings逐一对应原body_blocks，不能少写或重排；section_label由作者明确提供，不从事实数据中猜章节号。标题、段落与标签按真实中文字宽换行，超容量明确返回，不自动删文或缩小字号。

## 进入大纲、素材包和通用入口

大纲对应visual使用kind=diagram，含editorial_frame；此处指原生整页信息构图，不是关系图或SmartArt。不要同时设置relationship。purpose说明主题组织、阅读顺序或行动归纳的任务，source_refs引用实际资料。

准备完成后保存elements.json和真实预览；materials-plan像其他原生视觉一样提供source与preview。material-pack核对frame、title、body_blocks和页ID，复制完整片段。最终制作再次检查原文与对象，避免准备时保留了原文、入页时却替换内容。

brief-compose中对应的页面选择示例：

```json
{"slide_id":"cover","visual_id":"frame","layout":"cover","kicker":"方案汇报"}
```

divider/closing使用同名layout；kicker必须与准备片段相同，不再另传source_note、sections或另一份正文。页码由通用入口按整套顺序生成，片段中不提前写全局页码。

## 实际容量与编辑性

|页面|原文容量|原生构图|
|---|---|---|
|cover|1–2段简短说明，标题最多2行|左侧主题与简介，右侧文档叠层图形|
|divider|1段阅读引导，标题最多2行|章节号、竖向强调线、留白与正文引导|
|closing|1–3项行动，各有标题和说明|编号、行动名、说明与分隔线对齐|

固定常规宽屏13.333×7.5英寸。封面标题38pt、章节36pt、结尾34pt；正文22pt或19pt。容量最终由实际字宽、高度决定，表中的段落数不是允许任意长文。

封面文档图形为一组可编辑形状；结尾每个行动行为独立原生组，便于整体移动。图形笔画是文档隐喻，不编码数量。当前提供的是固定配方的自主实现，不代表可还原任意导入POTX/PPTX的几何或动态动画。

## 实际效果

28号任务用同一套系统组成封面→章节→图文→对照→数据→结尾六页，已用PowerPoint实际导出查看。真实预览和原始输入由frame-catalog及template-catalog的campus-complete-v1索引提供；候选模板未代替用户签署审美通过。
