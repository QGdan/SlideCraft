# 版式与素材设计方法

当前范围已澄清：常规Office/WPS PPT，重点是每页内容的内部排版，沿用任务画布；此前横向/纵向步骤对照只是局部试验。每次制作的布局计划、素材检索与入库步骤见[页内排版与素材调用工作流](页内排版与素材调用工作流.md)。

本轮视觉专项先解决两件事：同一内容如何安排更清楚；手上的素材如何选对位置。方法用于模板与美化阶段，事实与核心主张仍由大纲阶段确定。

## 先画阅读顺序，再排对象

每页先写清观众应依次看到什么，例如“标题→重点数字→比较依据”，或“任务→步骤→产出”。用大小、位置、对比和分组落实顺序。NN/g对视觉层级的解释适用于二维画面，但其网页示例中的像素字号不直接作为PPT规范。[来源](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/)

把最重要的信息形成主视觉，其余内容退为解释层。数据页应让人看出要比较的对象及意义；复杂表格不宜让每个单元格等强。Duarte用同一数据的不同表达说明了强调、注释及削减干扰的作用。[来源](https://www.duarte.com/blog/when-presenting-data-get-to-the-point-fast/)

## 本项目的版式决策表

已落地的8页构图、适用条件及复用顺序，见[视觉构图示例](视觉构图示例-20261021.md)；可编辑候选样稿位于 `templates/editorial-wine-v2/`。按页面任务选用，不将整套示例当成所有主题的固定模板。

| 内容任务 | 可先试的构图 | 重点检查 |
|---|---|---|
| 主题与情境 | 大图＋留白标题，或图文分栏 | 图像主体是否服务主题；标题区是否安静 |
| 单个结论 | 大字主张＋支持证据 | 视觉主次是否清楚；重要限制不能被丢掉 |
| 数据比较 | 图表＋近距离注释或重点数字 | 图型、标签、尺度与重点一致，装饰不抢数据 |
| 两种选择 | 并列对照，共用基线 | 对照维度对应，标题和正文靠近成组 |
| 多个步骤 | 横向总览，或纵向步骤＋侧图 | 阅读顺序、步骤说明和产出能否一一对应 |
| 章节过渡 | 少量文字＋概念场景 | 留白集中，避免整套都使用密集正文 |

这张表是起点，不是把所有页面锁死。技术汇报、阅读型文档和台上演讲的密度不同。Presentation Zen也区分演讲视觉与供阅读的材料，强调按受众和场景作设计选择。[来源](https://presentationzen.com/blog/what-is-good-presentation-design)

## 排版时的六个检查

1. **对齐线**：先定左右边界、图文分栏和标题线。相关对象沿共同轴线对齐，少用漂浮的小框。网格用于组织阅读，不要求每页构图相同。
2. **字级**：以标题、解释、辅助信息形成层次。同一角色跨页保持字号与字重，通常先用同一字体家族；长内容先改表达或换构图，再考虑字级。
3. **分组与留白**：同组内容靠近，组与组留出更明显的间距。空白应帮助定位主次；无目的的大洞与塞满画面都要调整。
4. **图文比例**：图像承担情境时，可以给它更大面积；步骤或数据才是主角时，避免大图挤压说明。画幅应由内容和图片原构图共同决定。
5. **对比**：重点使用角色色，辅助信息降级；在实际背景上检查文字与线条。整页都加粗或都高饱和会弱化层级。
6. **节奏**：用接触表检查连续页面的密度和重心。让封面、证据、比较、过程各承担自己的任务，同时保持字体、色板和边距连续。

字体、留白和网格如何协同，可参考NN/g对三种设计的具体拆解。本项目不照搬其网页字号或特定配色。[来源](https://www.nngroup.com/articles/why-does-design-look-good/)

## 先整理素材，再复用

素材记录应包含主题标签、适用角色、风格家族、留白位置、构图焦点、透明度、尺寸、来源、使用说明与SHA256。文件夹中的同图副本归为别名，保留旧路径以免破坏任务。

当前assets/library.json收录5项已逐图查看的项目生成素材，涵盖校园场景、报告封面、章节场景和透明主体；原来7个文件中的2个重复项作为别名。它是小型本地素材集，不是自动下载图库，也不是审美评分模型。

```powershell
# 在ppt-workflow目录运行；关键词用空格分隔
.\.venv\Scripts\python.exe -m ppt_workflow asset-search --query "校园 劳动" --use process --style campus-editorial
.\.venv\Scripts\python.exe -m ppt_workflow asset-search --query "审核" --use spot
.\.venv\Scripts\python.exe -m ppt_workflow asset-search --out runs/new-asset-gallery
```

命令只查本地人工标注目录，可按原始宽度过滤；不会证明裁切后的有效分辨率足够，也不会自动决定哪张最好看。图册引用项目内原图，移动时保留目录。标签命中排序不是语义模型或设计质量分数。

## 选图与放图

先按用途筛选：封面背景需要可放字的区域，章节图需要安静过渡，透明主体适合独立摆放。图中的模拟条形、圆环和报表不能充当真实数据；真实证据使用原始材料与原生图表。

选择后，将素材的id、path、source_id、license_note登记到请求assets，并保证sources有对应记录。不要把搜索结果整行直接塞入请求；其中用途、焦点等属于选择参考。将recommended_focus用于图片的image_focus，仍要看导图确认。

cover保持比例填充，会裁切边缘；contain完整显示并允许空白。透明主体优先contain。人物脸部、手部、视线方向和关键操作应在裁切后复核。当前透明放大镜图有浅色边缘，深底使用前要检查，不因带alpha就认为边缘完美。

同套材料尽量保持一致的明暗、材质、线条、透视与饱和度。校园酒红场景与报告青绿场景各有语境，混用要有明确理由。主题背景可重复，重复的小图不应成为每页固定装饰。

## 外部素材入口

| 入口 | 更合适的用途 | 本轮核对与边界 |
|---|---|---|
| 自有/用户原始照片 | 真实项目、实验、现场证据 | 核对真实出处和使用权限，不能用生成图冒充现场 |
| [Pexels](https://www.pexels.com/license/) | 场景照片和视频候选 | 官方许可列出免费使用及限制；按具体素材保留来源，不按“网上免费”笼统处理 |
| [Unsplash](https://unsplash.com/license) | 空间、环境、情绪场景候选 | 核对具体素材及许可，不批量复制成竞争图库 |
| [Lucide](https://lucide.dev/license) | 风格一致的线性图标候选 | 保留随文件的ISC及继承许可声明；本轮未安装或导入图标库 |
| 宿主imagegen | 无现成素材的概念场景 | 统一构图与材质，保存提示词；本轮对照复用原图，没有为增加数量再生图 |

本轮没有批量下载这些网站的素材。选定外部素材时再核对具体来源、人物/品牌使用情境和输出要求。

## 用对照判断，而不是用分数宣称美观

先冻结文字、数字、顺序、图像与讲述目的，只改布局、字级和裁切。检查内容是否完整，再查看全尺寸图和缩略图。记录适用场景与代价：横向版便于总览；纵向版更强调步骤阅读和人物，但会改变画面裁切与文字密度。主观偏好由用户决定，不将一个案例推广为通用优胜版式。
