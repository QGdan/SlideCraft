# 图片与原生图表联合表达

2026-10-22。新增image-chart组合构图：一张图片与一个紧凑原生比较图共同服务于本页主张。它是已有brief-compose的有限扩展，不把所有复杂页都压成左右两栏。

## 工作顺序与分工

1. 大纲Skill为图片和图表分别写visual任务，各自记录purpose、来源、事实及required。说明两项证据如何互补；图片不能代替数量证据，数据也不能代替实际场景。可用dominant_evidence说明重点。
2. 模板Skill在单图主导、单图表主导与image-chart之间选择，比较实际文案、图幅与数据标签容量。不要因为有两件素材就强行合并。
3. 制作Skill预制图片与紧凑图表，取得各自实际预览后放入material-pack。compact-chart-prepare只制图表，不自动下载图片或编写事实。
4. 模板样页审核后，brief-compose一次读取同页的两项素材。正文仍取原大纲，两个visual_id都有对象映射；多于这一组的必需素材不会被悄悄省略。
5. 实际导图查看主体、标签、零基线、来源和密度。美化/审核仍按既有阶段进行。

## 制作紧凑比较图

在项目虚拟环境运行，输出目录使用runs下的新路径：

```powershell
python -m ppt_workflow compact-chart-prepare --input examples/compact-chart-metadata.json --out runs/新任务/紧凑比较图
```

该命令归ppt-compose。`compact-chart-request/1`包含slide_id、element_id、theme、chart、sources、facts、source_refs、heading、source_note。theme使用微软雅黑与角色色ink/accent/muted/secondary/background；数据仍采用已有0.2 chart合同。

当前只支持非负数据、一个横条系列、2–4个短类别。明确指定一个强调类别，保持原顺序与数值，百分比沿用0–100约定；不自动归一化、舍弃系列或换图型。单位放在简短heading中，data labels精度继承已有格式规则。标题、来源、事实ID和可编辑图表一起输出。

紧凑图表为该构图预制，不能把原先“整幅图表＋侧边大结论”片段直接缩成小图；那样容易让结论、标签和来源失去可读性。

## 两项素材交给brief-compose

大纲中同一页有image与chart两个必需任务，素材包分别准备后，在composition-request中写：

```json
{
  "slide_id":"paired",
  "visual_id":"scene",
  "chart_visual_id":"widths",
  "layout":"image-chart",
  "kicker":"场景与数据联合判断",
  "image_heading":"校园协作场景",
  "image_note":"生成场景示意，非真实活动照片。",
  "focus":{"x":0.9,"y":0.5}
}
```

visual_id指定图片，chart_visual_id指定该页已准备的紧凑图表。图片沿用视觉需求中的fit；focus只改变主体裁切位置，需实际看图。图片的可见说明和必要署名放在左下，图表来源在右下，页码统一由整套生成。

正文为标题下的一行概述，完整读取body_blocks，不自动省略。左图区4.8×3.35英寸，右图区6.55×3.35英寸；固定常规宽屏、微软雅黑与既有角色色。复杂多系列、长类别、第三项必需素材或长篇解释，应换另一构图或由大纲调整页数。

bindings.json同时保存visual_ids与visual_elements_by_id，标清图片、图表及其说明分别对应哪些原生对象。源、事实与图片身份沿用任务素材包检查，图表仍是可编辑对象及嵌入数据，图片为可替换位图。

## 实际验证与使用边界

29号样例测量三份现有文件的原始像素宽度，保存路径、字节哈希、尺寸与事实JSON；图表读取1672、2560、1672px。左图展示相关校园协作场景，右图核对文件宽度，二者没有被解释为同一种评分。

像素更宽不等于图像更美、主题更相关或实际使用尺寸足够；后两项仍需看图与裁切。样例是文件属性与表达机制的验证，不是活动效果或行业统计。生成场景明确标示，不当作真实活动证据。本轮未调用生图或新在线服务。

原有封面、章节、单视觉内容页和行动结尾继续可用；image-chart仅为两项互补证据提供新选择。
