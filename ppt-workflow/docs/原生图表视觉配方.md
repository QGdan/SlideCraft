# 原生图表视觉配方

本轮解决图表的主次、标签和结论位置，不扩充图型。新增三种窄范围配方，实际预览可从chart-style-catalog读取；普通图表旧默认行为保留，只有显式使用presentation_preset时应用新字号、图例、网格与轴向规则。

| 配方ID | 范围 | 图文组织 |
|---|---|---|
| focus-comparison | 横条，2–6类别，单系列，恰好1个重点类别 | 左侧重点比较，右侧事实或已核对差值 |
| series-comparison | 分组柱图，2–4类别，恰好2系列 | 同基线比较、底部图例、右侧选定事实 |
| focus-trend | 折线，2–8有效且严格升序的YYYY-MM，1–2系列 | 少量网格/节点，减少数据标签堆叠，右侧解释选定事实 |

这些是“图表＋结论区”组合，区域至少11.4×4.2英寸，且必须完整落在任务画布内；不适合硬塞进较小卡片或复杂三栏。当前实际验证为常规16:9浅色背景，不代表任意尺寸、深色主题、字体均已验证。

## 在制作前准备

```powershell
# cwd: ppt-workflow；输出目录须为runs下新目录
.\.venv\Scripts\python.exe -m ppt_workflow chart-style-catalog
.\.venv\Scripts\python.exe -m ppt_workflow chart-prepare --input examples/chart-style-focus-comparison.json --out runs/新任务-图表准备
```

chart-style-catalog归ppt-template，chart-prepare归ppt-compose。示例使用合成数据，不能复制成业务事实；先从已批准大纲取得图表任务，准备真实sources/facts、单位和比较口径，选择合适配方再编写请求。

输入chart-style-request/1包含style_id、slide_id、element_id、canvas、rect、theme、chart、sources、facts、source_refs、callout、source_note、reason及version，完整样例见examples/chart-style-*.json。

theme声明font及ink/accent/muted/secondary/background角色色。类别和系列名最多8字符；右侧label最多12字符，value_template严格绑定单个事实，body_template的数值用事实占位符，不手写一个未核对的数字。callout只能引用图中事实或以这些事实为输入的已声明计算；命令不自动推断因果、生成故事或编造差值。

例如value_template为`{fact:gap}`，gap事实明确value、unit和formula。百分比相减应得到“百分点”，既有账本仍核对来源、范围、时期和comparison_group；跨时期差值不因配方方便而放宽已有公式合同。图表没有直接证明来源真实，外部source_truth_review未验证项仍交独立审核，不能删除。

label_format默认按数据精度选整数/一位/两位小数，百分比遵循0–100数值加字面%符号。超过两位小数时要求显式选择并审核显示精度，不自动把很小数值显示成0。格式只影响显示，不改变原值、类别、系列、事实ID或工作簿。百分比轴保留0–100；其他轴覆盖数据与零点，不裁切制造差异。

## 输出与合并

输出elements.json和preparation.json：原生chart、原生结论/说明文字、单位、分隔线与来源脚注，附来源/事实片段及请求和结果哈希。将elements合并到指定页，sources/facts按ID与内容去重并核对，source_refs并入对应页。不要把整个fragment直接放进deck合同，也不要覆盖同ID但内容不同的事实。

原生文本的text_template/fact_refs与图表fact_ids一起保留。合并后重新执行完整deck、账本、缓存和工作簿检查，再实际导图；准备成功只是待审资源，不自动批准模板或最终交付。图表本身已是视觉表达，不必再加无关配图。

## 真实软件结果与限制

三种原始原生PPT图表均通过PowerPoint实际导图和缓存/嵌入工作簿核对。首轮发现横条默认逆向显示类别；最终仅新配方设置由上到下的类别显示和贴轴刻度，不重排原始数组。柱图与折线保留同基线、统一色彩角色和底部图例。

**本机WPS转存存在数据保留问题**：虽然3页都能导图并重开，转存副本却丢失了3个图表的嵌入工作簿，关系变成空外链。不能因此宣称图表仍完整可编辑。现在wps-template在保存/回读后增加chart-preservation.json检查：原图有嵌入工作簿而副本丢失时返回failed，副本只保留作诊断，不作为最终交付。原始生产PPT仍保留完整数据，正式任务优先保留该原件并走PowerPoint路线；不把旧工作簿盲目回填到用户可能已改过的数据中。

该保护只核对原有工作簿是否保留，不替代数值、类型和公式检查；原图就缺乏可比较工作簿的项目列入uncompared，不能将其解释为数据已验证。WPS折线grouping=none还会让当前python-pptx无法识别类型，检查器现在记录unknown并继续数据核对，既不崩溃也不伪造passed。未修改WPS程序或原文档，未宣称通用根因已修复。

饼图、散点、地图、瀑布仍不在当前编译范围；图表数据的交互编辑往返没有因本次导图自动获得认证。每个任务仍需来源和效果审核。
