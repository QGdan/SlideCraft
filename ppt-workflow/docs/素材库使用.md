## 先检索，再准备

在ppt-workflow目录执行；所有输出目录须为runs下的新目录。

```powershell
# 新任务明确指定all，查图片和图标；省略--type保持旧图片检索行为
.\.venv\Scripts\python.exe -m ppt_workflow asset-search --type all --query "科研 团队" --out runs/新任务-检索
# 固定家族与分类；当前分类：education/research/team/process/data/tools/environment
.\.venv\Scripts\python.exe -m ppt_workflow asset-search --type icon --query "教学" --style tabler-outline --category education
# 候选原图查看后，记录本页选择理由与配色，准备可放入PPT的文件
.\.venv\Scripts\python.exe -m ppt_workflow asset-prepare --asset-id tabler:school --color 9B3045 --slide-id s1 --element-id s1-school --reason "教育主题节点，与整套outline图标一致" --out runs/新任务-学校图标
```

asset-search归ppt-template；asset-prepare归ppt-compose。新命令不调用模型，不自动批准阶段，也不自动把素材插进已存在的PPT。查询支持小型人工同义词表，例如科研→研究/实验、教学→教育/课堂；这是标签匹配，不是视觉语义模型。

默认limit=8，最多20；完整库分分类检索或查目录。min-width检查实际PNG像素宽度，不能据此判断SVG清晰度或裁切后分辨率。需要完整24项概览时查本轮交付中的图标接触表。

## 准备结果怎么进入PPT

每次asset-prepare生成：

- image.png：指定颜色的透明PNG，64–256px；默认256px，适合小型图标。不要放大为整页主图。
- source.svg：保留矢量路径，currentColor按指定颜色落实；PPT引擎当前使用PNG，SVG另存供后续编辑。
- LICENSE：上游MIT原文。
- preparation.json：原始库ID/提交/哈希、页与对象ID、选用理由、颜色和文件路径；含现有合同兼容的asset与source片段。

将preparation.json中的asset登记到spec.assets、source去重登记到spec.sources；在对应页source_refs引用其source.id。image元素的asset_id/asset_path取asset.id/path，使用image_fit:contain并设置实际rect。不要把整个preparation.json塞进deck合同。重复使用同一source.id时去重；位置、大小仍由逐页布局决定。

普通图片仍用已有素材登记流程；asset-prepare只支持本次固定Tabler子集，不是任意SVG转换器。颜色处理只改变透明PNG的主体颜色，保持透明度；SVG源文件不等于PPT里的原生形状。

制作前，将实际检索结果、选材记录、图表源数据与预览写入图表与素材准备清单.md；完成图片/原生图表/关系图准备，再批量排版。图标只是关系或概念表达的一部分，不能用几个装饰图标替代本页需要的主图/真实图表。

## 完整性与扩充

检索图标时核对PNG/SVG哈希、原始尺寸、许可与提交一致性；被改动的注册文件应停止使用并重新核对，不能悄悄更新哈希掩盖变化。同图不重复登记ID，私有素材不并入公共目录。

本轮导入脚本scripts/import_tabler_subset.py用于维护者固定版本导入，需要网络和显式的Node/sharp路径。普通用户无需运行它；运行时检索与配色仅使用现有Pillow依赖。原始包未随本轮自动升级，历史压缩包不代表当前新增命令。
