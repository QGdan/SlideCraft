# 插画与原生模块库

2026-10-19接入：2项经逐图筛选的Open Peeps人物插画，以及流程、双侧对比、行动与产出、里程碑时间线4类原生模块。合计可检索素材为5项原有图片＋24项图标＋2项插画；模块单独检索。普通检索与准备离线运行。

## 制作前如何调用

1. 大纲获批后，逐页明确文字、视觉证据、图片/图形和数据需求。
2. 模板Skill用asset-search和module-search查候选，查看真实预览后选择；素材并非越多越好，人物图仅适合对应语境。
3. 制作Skill用asset-prepare准备图片/图标/插画，用module-prepare准备原生对象片段；保存选用理由、来源与页/对象ID。
4. 图表与素材准备清单记录源文件与实际预览，随后再正式排版。按批准模板调整区域、角色色和字体，不把样件中的措辞、日期或主题色当作本任务内容。
5. 用实际Office导图与独立审核复核内容、密度、裁切和编辑边界。示意日期不能冒充实际计划，模块准备成功不等于内容已获批。

## 人物插画

[Open Peeps官网](https://www.openpeeps.com/)明确CC0；原始SVG、页面快照、CC0法律文本及SHA256保存在assets/illustrations/open-peeps。网站单项素材未给固定版本号，因此按原始SVG哈希固定内容，不虚构Git提交。

首批保留“举手示意人物”和“微笑交流人物”。另一项幻想人物不符合本轮风格，移出正式目录并保留在工程候选记录。人物组件不是完整背景场景，也不是实际人物身份或现场证据；需要完整场景时另行组织/制作，不把人物叠在任意页上作为图文设计完成的依据。

```powershell
# cwd：ppt-workflow；输出目录须为新的runs子目录
.\.venv\Scripts\python.exe -m ppt_workflow asset-search --type illustration --query "交流" --style open-peeps --out runs/新任务-插画候选
.\.venv\Scripts\python.exe -m ppt_workflow asset-prepare --asset-id peeps:peep-16 --slide-id s1 --element-id s1-person --reason "人物交流语境，配合本页流程" --out runs/新任务-人物准备
```

保留原色和宽高比，默认最长边1024px；size允许64–1024，仅缩小不放大。插画不接受图标用的--color，以免把黑白/多色细节整体抹掉。透明PNG通过现有image合同进入PPT，SVG另存；内部像素不具有原生图形编辑性。优先浅底，深底会弱化黑色轮廓。

省略--type仍只搜原5项图片，跨类型用--type all。全部31项不是31种风格，也不能理解为拥有丰富的任意主题图库。

## 原生模块

```powershell
.\.venv\Scripts\python.exe -m ppt_workflow module-search --query "流程"
.\.venv\Scripts\python.exe -m ppt_workflow module-search --query "对比"
.\.venv\Scripts\python.exe -m ppt_workflow module-prepare --input examples/module-request.json --out runs/新任务-流程准备
```

module-search归ppt-template；module-prepare归ppt-compose。模板目录templates/modules/library.json返回实际PowerPoint整页预览、示例请求及容量；预览右侧人物属于独立插画，模块自身不包含该图片。预览源PPTX和各页原始请求随目录保留，哈希用于核对，不用截图代替编辑对象。

| 模块ID | 输入与限制 | 原生输出 |
|---|---|---|
| native-process | 2–4步，每步title/body | 文本与方向箭头 |
| native-comparison | 恰好2侧，每侧title/body | 文本与非方向分隔线 |
| native-action | 2–4步，每步title/body/output | 任务、说明、产出文本与箭头 |
| native-timeline | 2–4点，每点date/title/body；date为有效且严格升序的YYYY-MM | 日期、里程碑、说明、时间轴与刻度 |

各模块标题最多8字符、正文最多20字符/3行，行动产出最多9字符。区域至少6英寸宽、2.8英寸高，且每项占宽不少于2.25英寸；字体固定18pt，太密则报错，不悄悄缩字。这只是首批可验证的窄合同，不能处理任意密集表格或自由关系图。

请求格式见examples/module-request.json；也可复制module-search返回的example_request，修改页/对象ID、rect、获批theme、items、source_refs和reason。示例source_refs中的workflow/scenario必须替换为本任务真实登记来源；模块只保留来源引用，不替你核查事实或批准语义。日期也必须来自本任务资料。

module-prepare输出request.json与elements.json。将elements.json的elements追加到对应slide.elements，并将source_refs并入该页已登记来源。合并后执行完整deck合同/原生对象检查，确保rect落在任务画布内、ID不冲突，不把整个fragment塞入deck合同。该命令不自动改已有PPT，也不自动批准阶段。

## 预览与实际验证

4张技术页已通过PowerPoint直接导图和WPS MCP副本保存、导图、独立进程回读。首轮发现说明与标题距离过大，第二轮对新模块收紧分组间距；原有compose_exhibit未改变。实际页面图与源请求存入模块目录，后续有布局变化应重新生成预览，不静默沿用旧截图。

另外对4类模块各一处原生标题实际修改、保存，并由独立WPS进程回读确认；该实测不扩大到人物像素重建、全部线条操作或任意模板兼容。

这些模块适合简明的过程与关系表达，尚未新增漏斗、矩阵、环形图、复杂组织结构或原生插画重建。正式PPT仍需真实内容、场景素材和图表配合，不把4类简单模块覆盖到所有页面。
