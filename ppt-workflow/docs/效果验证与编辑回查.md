# quality-v1 效果验证与编辑回查

2026-10-18，以三张劳动观内容候选页和两张模拟数据页检查新引擎。是工程试验，不登记业务批准，也不替代整套PPT验收。

## 可重复运行

在项目根目录ppt-workflow运行（out必须是全新runs子目录）：

```powershell
.\.venv\Scripts\python.exe scripts/verify_effects.py --node D:/node/node.exe --out runs/new-effect-pilot
```

脚本生成五页原生PPTX、deck-spec和对象/数据检查；校验错误返回非零。前三页使用实际案例来源、教学对照和建议行动，后两页明确标注模拟数据。此命令不启动Office，也不自动做视觉审阅。

再用render/windows.ps1导出本次真实预览；本机PowerPoint16.0/build20430已完成五页1600×900导出。受限环境可能拒绝COM或阻断stdio子进程，此时保留失败记录，在正常本机环境重试；不把沙箱失败直接解释为文件损坏。已有PowerPoint会话时渲染器拒绝接管。

## 本次发现并修正

- 非百分比图表原格式0.##会在PowerPoint中把整数显示为32.。改用General；比例标签仍用0.00"%"，数值采用0–100约定。
- 双系列折线每点同时显示数值会拥挤。默认保留原生系列、坐标轴与图例，关闭多系列折线数值标签。精确读数需编辑数据或另配数据表；单系列折线仍有数值标签。
- 行动组件的产出文字在浅背景上需要足够对比，本次试验使用更深的辅助文字色。

## 真实编辑与缓存检查

在独立副本中修改一处标题及柱图工作簿B2的合成值32→33，保存、重开。首次仅编辑工作簿后Close/Refresh，工作簿更新但图表cache仍是32，静态检查正确拒绝。

第二次在工作簿编辑后，按该图真实区域重新调用SetSourceData('Sheet1!$A$1:$C$5')并Refresh，再保存重开。独立检查确认标题更新、三图仍原生、修改图缓存及嵌入工作簿均与新spec一致。

这个区域只适用于本次测试，不可硬编码套用其他图表。真实任务须定位工作表和范围，修改后核查cache、公式、工作簿三者；COM返回成功或文件能重开并不足以证明数据已同步。

## 验证范围

本次通过的是指定五页和三张图的PowerPoint渲染及一次编辑往返。WPS当前会话、任意会员模板、Figma往返、生图效果没有在本轮重新验证。新候选布局更利于区分重点、情境与行动，但仍是简洁信息设计，没有验证照片、插画、复杂信息图或全套12页的最终风格，不能据此宣称“高质量问题已全部解决”。
