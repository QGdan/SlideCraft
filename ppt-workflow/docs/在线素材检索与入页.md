# 在线素材检索、缓存与入页

本接口面向PPT项目使用普通HTTPS API，不依赖Canva或额外MCP服务。旧asset-search/asset-prepare仍为离线路线，新增命令不会静默访问网络。

## 实际可用程度

- Iconify公开搜索已实测连通。Tabler集合在2026-10-19现场返回6,238项（含不同变体）；当前适配器只保留非filled候选、统一outline风格。集合总量不等于本地已下载量，也不保证每个主题都有合适图标。
- Wikimedia Commons搜索＋imageinfo元数据已连通；光伏主题有CC BY候选，并成功下载照片、放入PPT、由PowerPoint导出。图库不是按PPT审美筛过的精品库，仍须人工查看画面与来源。
- Openverse适配器具备搜索、分页、许可字段与下载逻辑。现场无许可筛选的一次基础请求成功，但带许可筛选的实际命令多次超时，尚不属于稳定的已验证照片路线。失败会写进results.json，不能伪装为零匹配或成功下载。
- 当前自动准备支持Tabler MIT、图片CC0/CC BY；SA/NC/ND及许可不清候选不会自动纳入。候选元数据仍须回到原来源核对。

## 调用顺序

从ppt-workflow目录运行，--out必须是runs下全新目录。

```powershell
# 图标：中文主题扩展为可审查的英文关键词
./.venv/Scripts/python.exe -X utf8 -m ppt_workflow asset-discover --query 汽车 --provider iconify --limit 8 --out runs/任务-汽车检索
# 照片：限定横图和原图宽度；筛选只针对当前一页候选，可能为空，需要继续翻页
./.venv/Scripts/python.exe -X utf8 -m ppt_workflow asset-discover --query 光伏 --provider commons --orientation landscape --min-width 1600 --limit 10 --out runs/任务-照片检索
# 未映射中文不能猜搜；明确传英文，可检索更细主题
./.venv/Scripts/python.exe -X utf8 -m ppt_workflow asset-discover --query 智能仓储 --keywords "warehouse robot" --provider commons --page 2 --out runs/任务-仓储第二页
```

结果含expanded_query、实际request_url、来源、作者、许可、原尺寸、远程预览、下一页及各服务失败情况；index.html用于看候选。默认all同时查Iconify/Openverse/Commons，一家失败返回partial（CLI退出码2），全部失败返回failed（退出码1），绝不自动替换图片类型。关键词匹配不等于视觉语义模型；农业→tractor等图标概念映射会反映在实际请求URL。

选择与内容、风格和构图对应的真实候选后再准备：

```powershell
# 照片：ID取本次results.json，不抄其他任务的ID
./.venv/Scripts/python.exe -X utf8 -m ppt_workflow asset-fetch --results runs/任务-照片检索/results.json --asset-id commons:本次ID --out runs/任务-照片准备
# 图标首次准备需要Node和sharp；路径由本机运行时发现，不硬编码为每台电脑通用路径
./.venv/Scripts/python.exe -X utf8 -m ppt_workflow asset-fetch --results runs/任务-汽车检索/results.json --asset-id iconify:tabler:car --color 9B3045 --node 本机node.exe --sharp 本机node_modules/sharp --out runs/任务-汽车准备
```

输出image.png、preparation.json、attribution.txt；图标另存SVG和MIT文本，照片保留下载原文件。原始下载最多12MB、静态JPEG/PNG/WEBP最多40MP；超限或不可解码直接失败。SVG保留源文件但PPT使用512px透明PNG，不能称为原生形状。接口图片以可替换对象进入PPT。

## 断网与可复用素材库

API响应存入assets/online-cache/queries，所选资源存入assets/online-cache/selected；包含抓取时间和校验和。查询响应是当时快照，需更新时不传--offline再次查询；离线不静默冒充最新结果。

- `asset-discover ... --offline`：查询同一关键词、同一来源和同一页的快照；没有缓存明确失败。
- `asset-discover --query 光伏 --provider cache --offline --out runs/任务-缓存检索`：用新的关键词搜索已经下载的素材，不要求与旧搜索词完全一致。
- `asset-fetch ... --offline`：复用同一素材/配色的已校验缓存，不需要Node/sharp；不存在或字节改变则失败。

已有所选素材的图册引用本地预览，其余候选预览需要联网。缓存是任务资料，不自动放进离线分发包，避免打包查询历史与绝对路径。没有批量镜像整个外部图库。

## 将素材真正放入PPT

asset-place接受asset-placement/1请求，针对已有0.2版英寸画布deck-spec，输出新deck-spec与placement.json，不直接接管正在编辑的用户文件。请求中的路径须为本项目内实际文件：

```json
{
  "version": "asset-placement/1",
  "deck": "项目绝对路径/runs/任务/deck-spec.json",
  "preparation": "项目绝对路径/runs/任务-照片准备/preparation.json",
  "slide_id": "s1",
  "element_id": "s1-photo",
  "rect": {"x": 0.65, "y": 2.15, "w": 7.8, "h": 4.3},
  "fit": "cover",
  "focus": {"x": 0.5, "y": 0.65},
  "credit_rect": {"x": 0.65, "y": 6.6, "w": 12, "h": 0.45},
  "reason": "画面中的光伏阵列与本页主题对应；裁切保留屋顶与阵列"
}
```

```powershell
./.venv/Scripts/python.exe -X utf8 -m ppt_workflow asset-place --input runs/任务/照片放置.json --out runs/任务-入页
# 由现有独立编辑引擎编译新spec，再使用目标软件导图
node engine/editorial_build.cjs runs/任务-入页/deck-spec.json runs/任务-入页/candidate.pptx
```

place会合并assets与sources、页面source_refs和图片元素；写入完整来源/许可/处理说明到备注。CC BY必须传credit_rect，生成可编辑署名文字；cover标注裁切。完整链接与许可保存在备注及attribution.txt，交付前检查信息是否清楚可访问。源deck保持不变。同页多项素材按顺序以上一次输出作为下一次输入。

校验包括图片哈希、对象ID、区域越界、焦点范围、来源ID冲突、schema和素材完整性。低有效PPI及与已有内容重叠会报告警告，不能把警告直接当作通过；透明留白、视觉焦点、文字遮挡与署名可读性仍须实际看图。自动入页是定位和登记工具，不会独立决定美观构图。

## 阶段职责与验收

模板Skill负责逐页素材需求、发现及真实候选预览；制作Skill负责fetch/place与对象对应；美化Skill检查裁切和角色色；审核Skill核对来源、许可、图片与主张的关系及目标软件页面。每次任务有需要图片/图标的页都实际检索、选择、记录原因，不能只因为接口存在就声称调用过。

当前效果证据：runs/online-placement-20261019-002/candidate.pptx及runs/online-placement-render-20261019-001。2页4项真实素材已在PowerPoint导出并查看。该结论不代表任意图库素材都可用、WPS转存或所有主题已覆盖。

接口依据：[Iconify搜索](https://iconify.design/docs/api/search.html)、[Openverse API](https://docs.openverse.org/api/)、[MediaWiki Imageinfo](https://www.mediawiki.org/wiki/API:Imageinfo)、[MediaWiki搜索](https://www.mediawiki.org/wiki/API:Search)。现场证据优先于接口文档的存在。


实际编译入口更新（2026-10-20）：使用`python -m ppt_workflow editorial-build --input <spec.json> --design <design-system.json> --node <node.exe> --out <全新runs目录>`。该入口保留原始包与规范化日志，并检查原生对象及包结构。底层JS输出可能含已知PptxGenJS多余母版声明，不能直接凭能导图就交付；design参数只支持已实现的布局定义，不声称重建任意外部模板。
