# 页内排版与素材调用工作流

最新默认顺序与交接门禁以[大纲驱动与任务素材包](大纲驱动与任务素材包.md)为准：详细大纲审核→任务素材预备→模板/代表页审核→逐页制作。

## 范围

用户已澄清：制作 Office/WPS 中的常规 PPT。沿用任务指定的画布；没有特殊要求时使用常规 16:9，不改成竖版。“布局”指每一页中文字、图表、图片及辅助元素的位置、大小、分组和阅读顺序。横排或竖排步骤只是局部组织手法，不能代替完整的页内设计。

## 制作前先准备图、表与素材

本项目按用户要求，以每页图文结合为默认交付要求。文字搭配与本页结论有关的图片、原生图表或关系/流程图形；图标、色块和边框不能单独充当完成图文设计的依据。不是要求每页同时塞入照片、图表和文字三种对象，也不能为了配图编造数据。

大纲获批后、正式逐页制作前，先整理 `图表与素材准备清单.md`：逐页结论、图文组合、所需图片/图形、数据来源与单位、拟用图型、素材候选及取舍、真实预览路径、可编辑要求和待解决缺口。先核对资料与数据，再检索/生成相关图片，制作图表草稿和关系图草稿，统一风格并查看预览。缺少数据时使用真实资料支持的概念/关系表达，不生成虚假统计图。

准备工作分属原有阶段：ppt-outline整理资料和数据需求；ppt-template确定视觉规范及代表页用图；ppt-compose在模板最终提交前执行素材预制和material-pack子任务，正式制作在模板与素材包获批后进行。准备清单随原阶段成果一起审核，不新增第七个Skill或伪造独立审批。没有可用素材或关键数据仍缺失时记录缺口，不能直接宣称已具备制作条件。素材准备与布局草图允许相互调整，但不得跳过准备直接批量填字。

开源素材库选型、结构和分步接入建议见[开源素材库研究与接入方案](开源素材库研究与接入方案.md)。已优先接入24项Tabler图标，支持中文检索、配色准备与PNG引擎登记；实际命令见[素材库使用](素材库使用.md)。Iconify/Commons在线接口和Open Peeps已接入，实际状态见[在线素材检索与入页](在线素材检索与入页.md)。

## 每页内容布局与素材适配

1. 从已批准大纲提取本页结论、必须呈现的证据、文字量与主要视觉任务。确定观众先看什么、再看什么，不先塞满固定数量的卡片。
2. 画内容区域草图：标题、主证据、解释、来源。明确各区域的相对位置与占比、共同对齐线和留白。主题配图不能压缩真实图表与标签的阅读空间。
3. 按内容选择结构，而不是整套机械套一种结构：结论配主图；图表配近距离注释；案例图片配说明；同维度比较；步骤与结果对应；必要时以原生关系图代替段落。每页保留文字与有表达作用的视觉内容，避免纯段落页。
4. 列素材需求：主题、角色、风格、横竖构图/长宽比、放置区域、需要的留白与主体位置、是否需要可编辑。素材构图方向不等于幻灯片方向。
5. 实际检索素材库，保存检索词和返回候选；看候选原图后记录选中或不用的理由。没有合适结果时补充检索/生成或制作原生元素，不把不相关图片硬塞进页面。
6. 按批准模板组织原生文字、图表、形状与素材。检查字号、对齐、组间距、图片裁切、视觉重心和证据突出程度；超出引擎能力时做实际适配，不仅写配置。
7. 真实导图查看每页和整套接触表；记录本页最先被看见的内容、可读性问题、素材是否有用，再修改。审核仍由独立审核 Skill 执行。

模板阶段固定视觉语言并打代表样页，制作阶段逐页落实，美化阶段修复具体页面问题；不把每页重新设计都变成更换整套模板。

## 素材库如何参与每次制作

素材库由三部分组成：项目内原文件、可检索目录、来源与使用记录。当前 `assets/library.json` 已有 5 项去重位图，`asset-search` 可真实检索；它还不是丰富完整的通用图库。

- **图片/插画/透明主体**：登记目录中的主题、风格、用途、留白、焦点、原尺寸、来源及 SHA256；通过现有命令检索。
- **图标/矢量**：当前24项Tabler在独立目录，asset-search --type icon/all可查询；asset-prepare保留SVG并准备配色PNG与许可。现有PPT引擎采用PNG，未实现SVG转原生形状。优先同一风格家族。
- **可编辑模块**：模板图表、流程、时间线、表格等归模板/组件资源。先用 `template-catalog` 和真实模板盘点查看已有能力；不能把它们当成截图素材。图表数据来自本任务资料。
- **用户资料**：真实照片、品牌资产、研究图表优先进入任务私有材料；未经许可不并入可分发公共素材库。

在 `ppt-workflow` 目录执行，输出目录必须是新的：

```powershell
.\.venv\Scripts\python.exe -m ppt_workflow asset-search --query "校园 劳动" --use process --style campus-editorial --out runs/任务名-素材检索01
.\.venv\Scripts\python.exe -m ppt_workflow asset-search --query "审核" --use spot --out runs/任务名-素材检索02
.\.venv\Scripts\python.exe -m ppt_workflow template-catalog --help
```

每个检索目录保存 `results.json` 和 `index.html`；后者是候选图册，不是自动设计结果。先按主题检索，必要时逐步放宽风格/用途过滤，仍不匹配就明确缺口。`--min-width` 仅按原图宽度过滤，实际裁切分辨率仍需复核。

### 逐页使用记录

每个任务保存一份 `page-visual-plan.md`，按页记录：

| 字段 | 要写的内容 |
|---|---|
| 页ID与结论 | 对应获批大纲，不重写事实 |
| 阅读顺序 | 例如标题→图表重点→原因注释 |
| 内容区域 | 文字、图表、图片的位置/相对占比；共同对齐线 |
| 素材需求 | 用途、主题、风格、比例、留白、编辑要求 |
| 检索证据 | 图片/图标的实际检索结果；使用自有图片或自制原生图表/图形时记录来源和制作路径 |
| 取舍 | 选中素材 ID、来源、选择理由；或无合适结果及处理 |
| 放置 | 裁切/完整显示、主体位置、关联 slide/element ID |
| 导图复核 | 真实截图路径、观察到的问题与修改 |

这是 Skill 交接的设计附件，不是已实现的新 CLI 合同，也不声称引擎自动强制执行。模板阶段的 `asset_guidance`、制作阶段的 `implementation_notes` 可引用真实附件路径，沿用各自合同字段。

## 素材增长与回收

新增asset-discover负责在线检索、asset-fetch负责单项下载缓存，material-pack集中到任务素材目录；旧asset-search仍为离线查询。需要补充时：检索可用外部来源或调用当次可用的生图工具，查看原图并核对来源，保存文件与生成/许可记录；由 Skill 维护 `assets/library.json`，沿用实际字段，不编造下载链接或权限。登记哈希、原始尺寸、标签、风格、用途、留白和限制；同图用 aliases，旧任务引用保持不动。入库后再次运行实际 `asset-search` 验证能查到，随后核对页面渲染。

任务结束只将可复用且权限允许的素材加入公共目录；私有素材留在任务中，失败候选保留检索记录即可。新素材入库可以扩大下次检索范围，不等于必须在下次使用。库缺乏某类素材时，如实写缺口。

## 审核重点

审核页内内容主次、图表与注释对应、文字可读性、图文配合、留白、裁切和跨页一致性，同时核对准备清单与实际图片/图表预览。逐页检查文字是否搭配有意义的视觉内容，纯文字堆砌或仅靠装饰图标凑图的页面退回改进；原生图表配注释可以满足图文结合，不必再塞照片。有外部素材需求却没有检索或处理说明时退回补齐。检索命中率、图片数量与自动化测试数不能代表设计质量。
