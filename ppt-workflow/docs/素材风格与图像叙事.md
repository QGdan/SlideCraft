# 素材风格、检索要求与图像叙事

2026-10-22。第三批迁移采用Baoyu固定版本中的共享风格说明思路，并沿用本项目原生文字/图表路线。只自主实现素材规划与使用记录，没有复制整页位图生成工作流。

## 六阶段中的工作顺序

1. **大纲Skill**：写实际正文、来源和逐页视觉任务。对图片/图标补visual_direction：角色、主体、画幅、留白、媒介、缩放方式和应避开的内容。角色区分evidence真实证据、context场景、metaphor概念示意、decoration装饰；不要把场景照当成本项目现场证明。
2. **模板Skill**：在已有视觉方向或候选模板范围内维护独立asset-style.json，通过asset-plan请求的style字段引用。大纲brief不必被模板选择改写；兼容已有内嵌asset_style。执行asset-plan，将统一材质、线条、色彩、基调传给每个素材任务，得到检索要求、计划提示词和计划参考。前期风格可作为候选；模板确定后若改变风格，重新选材/记录并更新素材包，而非沿用旧记录冒称一致。
3. **制作Skill准备子任务**：使用已有asset-discover/asset-fetch检索和下载，或使用当时可用的生图工具。实际看图，确认主题、裁切和风格；执行asset-record记录实际操作、提示词、参考、选用理由和观察。提示词只能填写真实提交过的文字。
4. **任务素材包**：material-pack复制图片、来源、许可、完整风格/使用记录及实际参考图片。旧任务无新字段仍兼容；声明visual_direction的任务必须匹配准备记录，换风格后旧素材记录不能直接通过。原生图表/图形仍保存源和实际预览。
5. **模板代表页→逐页制作→美化→审核**：图片按预定fit入页，检查主体和留白；趋势数据、标题、标签与说明保持原生。审核实际导图中的图文比例和跨页一致性。工程元信息放记录，不铺进PPT页脚。

## 命令与输入

在项目虚拟环境运行，所有输出使用runs下的新目录：

```powershell
python -m ppt_workflow asset-plan --input runs/任务/asset-plan-request.json --out runs/任务/素材计划
python -m ppt_workflow asset-record --input runs/任务/asset-record-request.json --out runs/任务/已选素材
python -m ppt_workflow trend-prepare --input runs/任务/trend-request.json --out runs/任务/趋势图
```

asset-plan归ppt-template；asset-record、trend-prepare归ppt-compose。它们是实用程序，不自动调用模型、下载素材或批准模板。

计划请求为 `asset-plan-request/1`，字段outline与brief指向项目内实际JSON，style指向独立asset-style.json。materials-plan的asset_style也指向这个文件，素材包保存其快照与哈希；旧内嵌格式仍兼容。可用examples/asset-style.json和examples/asset-visual-direction.json作为字段参考：

- `asset_style`：version=`visual-style/1`、id、medium（photography/illustration/mixed）、colors（至少background/ink/accent）、material、line、tone、references（计划参考地址/说明列表）。
- `visual_direction`：role、medium（photography/illustration/icon）、subject、aspect_ratio（例如16:9）、negative_space（left/right/top/bottom/none）、fit（contain/cover）、avoid列表。

计划输出中的search给出query、显式keywords、provider、orientation和min_width，可传入既有asset-discover。照片默认Commons、图标Iconify；素材不足时可换其他已支持来源并记录。画幅只映射横/竖/方筛选，不承诺搜索接口识别图片中的留白或审美。主体、光线、材质和裁切仍由实际看图决定，不用标签分数假装视觉判断。

`asset-record-request/1`字段：plan、slide_id、visual_id、preparation、operation、actual_tool、actual_prompt、actual_references、selection_reason、review_notes。

- operation=generated须写实际提示词与工具；actual_references仅填写实际使用的本地PNG/JPEG/WebP路径，快照随素材复制并保存哈希。没有参考则[]。不能只把计划参考列表当实际输入。
- operation=retrieved或existing时actual_prompt为空；旧素材历史生成信息仍保留在原有来源记录，不能伪造本次调用。
- evidence任务不接受generated记录。context插画和照片同样不能代替事实图表。
- 输出新preparation.json包含visual_design，源文件不变；图片、许可和实际参考文件在同一目录。进入material-pack后仍保留完整记录。局部重做只改相应visual_id，重新准备和封存，不覆盖原任务。

## 图片叙事与证据主导构图

第二批image-led/image-balanced继续用于图旁说明。新增image-story用于“上方场景图，下方两段短解释”，通过layout-plan/page-prepare显式指定layout=image-story，实际文字决定是否需要拆页。新增固定正文带在5.3英寸以下，标题仍预留空间；图片区域按标题高度调整。长篇解释优先使用其他布局，不能把文字缩小塞进说明带。

图片为场景时可以明确cover裁切，并在实际导图核对；证据需要保留全貌时选contain。asset-place对带记录的素材检查页ID和fit，素材包合并检查也核对fit。负空间是选材要求，没有自动检测功能。

## 原生趋势注释

trend-prepare输入 `trend-annotation-request/1`，字段chart_request为已有完整focus-trend请求，annotations含1–2个 `{category,text_template}`。例如：

```json
{"category":"2026-01","text_template":"方案甲 {fact:line-a-0}"}
```

注释只绑定对应月份的图表事实，数字须来自fact模板，单位随事实输出；日期必须存在且不重复。短注释放在图表上方，图表高度相应调整；它是带明确月份的说明带，**没有假装精准定位Office图表内部的数据点**，不表达未经资料支持的因果事件。注释、结论、原生图表及嵌入数据继续可编辑。当前限定微软雅黑、现有focus-trend和一行短注释。

## 能力与证据

26号任务用缓存中的Commons照片实际走通检索、选中下载、风格记录、素材包、入页、PowerPoint导图。复用已有公共接口，本批没有重新证明在线服务的实时可用性；缓存可用不等于联网成功。生图计划/记录机制已实现，本批没有调用生图模型，不声称测试了某模型接口。

四页简报使用同一色板、字体、图片处理与图表语法；趋势数据明确为合成示意，非业务实测。照片仅使用一次，其他页采用原生图形。模板目录中的solar-editorial-v1为可复用候选及实际参考样件，仍需用户审核，封面图案不冒充通用封面生成器。
