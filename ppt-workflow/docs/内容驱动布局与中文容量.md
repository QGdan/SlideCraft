# 内容驱动布局与中文容量

2026-10-22。参考23号源码调研中的布局树、空间预留与真实样页方法，自主实现；没有复制上游运行代码。本功能服务已有六阶段，不增加阶段。

## 在工作流中的位置

1. 大纲阶段整理每页的实际标题、有序正文段落、证据类型、来源和阅读顺序。不要只给“这里放文案”。数量事实继续使用项目事实账本与图表模板；关系内容继续用relationship-prepare。
2. 模板阶段运行 `layout-plan` 比较支持的版式。先为标题与来源预留空间，再测量正文。看选择理由、页数与替代方案，用真实图片和图表生成代表页后交用户审核。模板颜色变化可通过请求的六个角色色调整。
3. 制作阶段在已批准的模板范围内运行 `page-prepare`，获得原生文字片段与证据区域。正文按输入顺序阅读，双栏是先左后右；没有自动删字、概括或缩小字号。拆页是待审核的排版建议，不能代替修改已批准大纲。
4. 将证据区交给已有 `asset-place` 或 `chart-prepare`。图片使用任务素材包，核对主体与裁切，保留许可。图表保留facts、sources、fact_refs和text_template；不能把数字结论变成没有绑定的普通文案。已有图表配方自带来源声明，所以chart-focus不重复生成来源页脚。图片入页的许可说明可替换通用来源框，避免重复。
5. 合并片段后使用 `editorial-build`，在实际Office/WPS导出并查看。中文字体测量是容量估计，最终效果以实际渲染为准。

## 两个入口

在项目虚拟环境运行，输入和输出都在项目内；输出目录必须是runs下的新目录：

```powershell
python -m ppt_workflow layout-plan --input runs/任务/body-request.json --out runs/任务/布局候选
python -m ppt_workflow page-prepare --input runs/任务/body-request.json --out runs/任务/正文片段
python -m ppt_workflow template-catalog
```

`layout-plan`归ppt-template；`page-prepare`归ppt-compose。前者保存layout-plan.json，后者再生成pages.json。不是直接修改正在打开的PPT或在线模板。

请求示例：

```json
{
  "version":"layout-request/1",
  "slide_id":"materials",
  "title":"先准备素材，再按大纲逐页制作",
  "kicker":"制作方法",
  "source_note":"来源：本项目自撰工作方法。",
  "evidence":"none",
  "blocks":[
    {"id":"prepare","heading":"按页面主张准备素材","text":"逐页记录需要的图片、图表和来源，将选定素材放入当前任务文件夹。"},
    {"id":"compose","heading":"用真实内容检查容量","text":"带入实际标题和正文选择模板，再组织证据与说明。"}
  ]
}
```

可选：`layout`显式指定下表配方；`page_limit`是这次输入最多允许的页数，默认不锁定；`colors`须给全ink/accent/muted/background/surface/line六个十六进制角色色。锁定页数放不下时返回needs_input，保存完整原文与建议，**不生成pages.json**。此时调整页数或请作者明确改写，不能把等待当作批准。

## 实际实现范围

画布固定为常规宽屏13.333×7.5英寸，字体为已安装的微软雅黑。标题30pt，正文19pt，小节20pt。两行标题会压低内容区；来源最多两行。暂不支持任意字体、任意画布自动布局。

|配方|适用输入|处理|
|---|---|---|
|text-wide|连续正文|宽单栏，按段落顺序|
|text-columns|较长分节正文|先左后右，整页排完再续页|
|image-led|图片证据配短文|较大左图区，右侧说明|
|image-balanced|图文说明较长|增加正文宽度|
|chart-focus|图表与事实结论|预留已有原生图表配方所需完整区域，不接额外正文块|

选择规则很简单且公开：先筛证据类型，再比较实际测量的页数；同页数时，长分节正文倾向双栏，图片倾向保留更大图幅。可显式指定适配布局，不做语义模型推断，不机械轮换版式。暂不代替封面、复杂关系图、时间线或表格的专用制作。

## 长内容与来源映射

按微软雅黑真实字宽处理中文、数字和英文词组；中文禁则避免指定的收尾标点出现在新行起首，括号开端不单独留在行末。保留原始空格与显式换行。超宽不可断英文词组返回换布局提示。

plan保存source_request原文，每个正文片段含block_id、source_start/source_end与source_text，body_lines中start/end相对于该正文块原文。所有片段拼接应严格还原原文；渲染仅插入换行。跨页续段会加“（续）”标题，原文不变。数字来源和事实模板由已有账本负责，本工具不验证业务事实或代做事实绑定。

长篇阅读稿与现场演示稿的容量要求不同。这里的长正文代表页用于展示完整内容适配；正式演示可由作者压缩叙述或拆分叙事，不能把“装得下”当作设计完成。

## 模板索引与代表页

`template-catalog`保留原蓝图列表，并新增capacity_templates，读取templates/content-editorial-v1/index.json。该条目是带真实内容预览的候选视觉系统，通过page-prepare制作，不是假装已经实现的blueprint。

索引保存角色色、字体、支持配方、容量策略与三张实际导图。代表页覆盖text-columns、image-led、chart-focus；另外两个变体有容量分配实现，但没有单独视觉样页。候选未自动获得用户审美批准。
